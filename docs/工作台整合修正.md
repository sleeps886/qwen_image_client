# 工作台整合修正

日期：2026-11-25。用户明确要求完善原轨迹工作台，不接受另开页面作为日常流程。

## 入口与布局

- 主入口仍是`/incremental`，保留原会话列表、文件库、浏览分组、按点/同步组抽样、聊天、完整流式正文、人工确认及空间绘图。
- 删除侧栏“实时增量接入v2”分叉导航。普通`/live`链接重定向回原工作台；原实验视图仅保留`?diagnostic=1`用于开发兼容验证，不是用户操作入口。
- 新增“本次导入方式”：替换当前浏览数据（保留旧会话）或追加到当前会话。默认替换，避免旧操作静默改变意义；需要持续追加时明确选追加。

## 在原工作台中的操作

1. 新导入数据照常选点、免费准备。新建的混合会话自动建立持久化输入账本，不增加模型调用。
2. 已有旧会话点击“启用当前会话追加（免费）”，核对时间基准；旧轮次、模型正文、调用次数、失败记录和空间结果保留，不自动重跑。
3. 文件追加：选择“追加到当前会话”，核对来源ID，再拖入ZIP/JSON。单点/批次也可在该侧栏展开JSON输入。
4. 新点只入账，不自动勾选、不混入正在运行的快照；下一轮按原流程选点、免费准备、明确授权。
5. 如果接入回执断线，使用“重发原接入请求”复用原幂等键，不会再次调用模型。
6. 人工确认与第二次空间模型绘图继续使用原工作台，不降级成另一套仅方位页面。已确认集合和旧空间图仍按原协议保存。

来源ID不是目标身份。相同来源同编号相同值记duplicate，不同值记conflict，旧值不覆盖；不同时钟不直接追加。追加后的聚合会话有独立账本，删除其中一个源文件不代表删除整个聚合会话；删除原单文件浏览时原有清空逻辑保留。

## 数据与并发

会话目录新增`observations.sqlite3`，复用v2接入校验、SQLite事务、幂等与隔离模块；输入事实由该账本持久保存。现有`state.json`继续保存关联投影和空间结果，点目录作为兼容缓存由账本补齐，不另开用户工作流。

追加不写正在执行的`state.json`，不争抢模型全局锁。旧模型结束提交投影后，读取时仍从账本补齐后来收到的点和稳定别名，因此不会被旧快照覆盖。匿名编号只由程序分配，不修复模型猜错的编号。

本轮快照知识截止按实际纳入的测量/历史接收序号计算，不因未选中的新到点改变原授权摘要。已有失败回复仍按原快照读取/校验，不用新版候选静默改写旧答案。

## 重叠候选改进

- 启用持久化输入的会话采用覆盖全时间范围的重叠滚动窗口，不再只提供前/中/后三个窗口。
- 输入明确列出`candidate_competition`：哪个观测同时支持哪些R候选。
- 增加`candidate_refs`数组：模型可显式把多个可接续同阵R候选放在同一条片段链，交叠支持只计一次。
- 这不是自动合并模型输出。两个不同N轨迹重复确定占用同一点，仍严格拒绝；理由写competing也不会自动成为合法歧义，模型必须明确使用ambiguous或unassigned。
- 空间配对继续对实际支持集合校验；组合候选需重算配对证据，不能沿用不匹配的P证书。

## 验证

- 新增6项原工作台整合测试：原入口、回执幂等/冲突、未选新点不改变快照、旧失败记录启用保留、滚动候选同链合并、模型运行期间追加且提交后不丢点。
- 核心关联与整合回归129项通过；空间绘图等另一组回归74项通过（两组包含重复用例，不相加宣称独立总数）；Node测试4组通过。
- 浏览器`check_unified_workspace.js`通过：同一工作台、同一会话，运行期间追加、冻结快照、历史接续、空间绘图入口保留、文件追加、刷新恢复及旧链接回到原页面。独立8891伪网关，1次伪调用，0真实付费调用。
- 原单点/异步/抽样浏览器回归通过，原始1224点不因抽样修改。
- 广泛回归485项通过，另120个子测试通过；沿用明确排除的3项旧失败断言和3个未跑的重数值旧测试文件，不声称整个仓库全绿。

边界：这次整合复用了输入账本与候选链能力，并保留原模型执行/空间结果协议；没有把原空间流程替换成实验`bearing-prediction-v1`，也不声称原混合任务因此自动获得实验任务系统的所有跨进程恢复能力。真实模型精度与异步空间求解仍需独立验证。

后端及前端均有改动，需等当前任务结束后重启后端再刷新原页面。未在开发过程中重启用户生产服务，未调用真实付费模型。
