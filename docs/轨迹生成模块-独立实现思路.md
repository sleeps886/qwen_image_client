# 轨迹生成模块：独立实现思路

## 1. 文档定位

本文说明如何从零实现一个可独立使用的轨迹生成模块，不依赖某个项目的页面、目录结构、历史结果、工作流框架或模型服务。

目标场景：从声呐等方位—时间图片中提取观测，结合可选的平台运动参数，生成方位轨迹或空间候选轨迹，最后输出结构化数据及可视化图片。

本文是实现设计，不代表算法已经实现或通过真实精度验收。示例字段和接口均为建议契约，不要求与任何已有系统兼容。

## 2. 核心思路

把“生成轨迹”拆成三个独立问题：

1. **提取观测**：图片中的亮带在什么时间、什么角度出现？
2. **估计运动**：哪些观测属于同一目标？现有信息是否足以推断位置和运动？
3. **展示结果**：将已经生成的点位画出来，不能通过绘图补造定位结论。

```text
图片 + 标定信息 ─→ 观测提取 ─┐
                           ├→ 观测校验 → 轨迹关联 → 方位轨迹
结构化观测 ────────────────┘                  │
                                            ├→ 可选空间定位 → 空间候选
已知平台运动 ────────────────────────────────┘

方位轨迹 / 空间候选 → 质量诊断 → 标准结果 → JSON / PNG / 调用方界面
```

基础版本优先支持“结构化点位输入 → 轨迹输出”，再增加图片识别。这样可以独立验证算法，避免把图片识别错误、目标关联错误和定位错误混在一起。

## 3. 输入分级与能力边界

| 输入条件 | 可交付结果 | 不应承诺 |
|---|---|---|
| 已有轨迹点 | 校验、分段与绘图 | 证明输入点真实 |
| 方位—时间观测 | 方位轨迹、关联候选 | 唯一空间位置 |
| 单阵方位 + 平台运动 | 带运动假设的候选解，或不可定位原因 | 所有情况下都能恢复距离 |
| 同步双阵方位 + 两阵位置 | 满足几何条件的空间候选 | 自动消除所有左右舷歧义 |
| 图片但缺少轴标定 | 待标定提示，或人工确认的标定草稿 | 直接给出可靠角度、时间或地理轨迹 |

折叠舷角不是绝对航向；方位—时间曲线也不是空间运动曲线。缺少距离信息时，不能将角度变化直接缩放成地理轨迹。

## 4. 独立模块的组成

### 4.1 输入与标定

职责：把外部图片或文件转换成统一输入，不负责定位和绘图。

图片标定至少需要：
- 有效绘图区，不包含标题、坐标文字、图例和边框。
- 像素轴与时间/方位轴的对应关系及正方向。
- 时间范围、角度范围、角度定义（绝对方位/相对方位/折叠舷角）。
- 通道标识、采集时间基准；多阵列还需时间同步信息。

轴为线性时可采用线性映射，例如：

```text
数值 = 数值起点 + (像素坐标 - 像素起点)
                     / (像素终点 - 像素起点) × (数值终点 - 数值起点)
```

像素起终点可反向，因此时间向下增长和向上增长都可处理。非线性坐标轴必须另用明确标定函数，不能默认线性。

标定可以由人工填写、读取图像元信息或识别坐标轴获得；自动识别的标定应记录来源与待确认项。

### 4.2 观测提取

提供可替换的提取器，而不是把算法绑定某个模型：

**传统图像方案**
1. 裁剪绘图区，处理背景、网格和非数据文字。
2. 按时间切片计算角度方向的强度剖面。
3. 提取局部峰值，保存峰中心、峰宽和强度等诊断量。
4. 将峰值像素转换成时间—方位观测。

**模型辅助方案**
1. 向模型提供图片、标定定义和严格输出格式。
2. 只要求输出观测点、候选片段及来源，优先不让模型直接编造最终空间坐标。
3. 对返回 JSON 做数值、范围、时间和来源校验。
4. 失败时返回错误或转人工确认，不自动把自然语言描述转换成坐标。

两种方案统一输出 Observation，后续关联与定位不关心观测由哪个工具产生。峰强度、模型自评分不能未经校准就称为概率置信度。

### 4.3 轨迹关联

目标：判断相邻时刻哪些点属于同一目标，同时保留交叉、遮挡和断段的不确定性。

最小实现：
1. 按时间排序，在小时间窗内构建候选连接。
2. 根据最大时间间隔、角度变化率、预测残差进行门控。
3. 计算候选连接代价，例如预测角度偏差、变化率偏差、漏测惩罚。
4. 使用一对一分配或路径搜索生成局部轨迹片段。
5. 对交叉和多解情况保留多个关联假设，而非强制连接。

```text
连接代价 = w1 × 角度预测残差
         + w2 × 变化率差异
         + w3 × 时间缺口惩罚
```

权重和门限属于配置，应通过样本验证，不在代码里写死为普遍规律。不同角度定义须使用对应残差函数：绝对方位可用圆周差，折叠舷角不能直接套用普通 360° 环绕距离。

轨迹身份与镜像分支分开管理：同一目标的多个空间候选不能计成多个已确认目标。跨缺口连线应标记为推断，观测点和插值点必须可区分。

### 4.4 空间定位（可选能力）

只有在已知阵列位置、方向、时间同步及角度含义时启用。

先统一到局部平面坐标：x 向东、y 向北、单位米；明确原点。距离较大或投影误差不可忽略时，替换坐标转换策略，而不是在定位函数里混用经纬度和米。

若绝对方位 θ 定义为从正北顺时针计量，对应单位方向为：

```text
d(θ) = (sin θ, cos θ)
射线位置 = 阵列位置 p(t) + λ × d(θ)，λ ≥ 0
```

双阵定位实现步骤：
1. 根据平台运动及阵列相对安装位置，计算每时刻两阵的位置与朝向。
2. 将相对角转换为绝对方位；折叠角按定义枚举左右舷分支。
3. 对同步观测进行候选配对，求两条射线交点或带约束的最小二乘近交点。
4. 拒绝射线背向交点、近乎平行、超出配置范围或时间不同步的组合。
5. 输出交会角、射线残差、分支标识和拒绝原因。

有噪声时不要假设射线精确相交。交会角很小时位置误差可能放大，应降级为弱定位候选或拒绝，不靠裁剪坐标伪装稳定。

单阵纯方位定位应作为后续高级能力：需要足够时间跨度、运动假设和可辨识性分析。几何条件不足时，直接输出 bearing_time，而不是强行拟合唯一空间曲线。

### 4.5 连续运动估计与质量检查

第一版可从匀速模型开始：

```text
x(t) = x0 + vx × (t - t0)
y(t) = y0 + vy × (t - t0)
```

通过最小二乘或鲁棒拟合估计参数；确认有需要后，再加入分段匀速、转弯等模型。复杂度增加应有样本依据，不能仅凭更平滑选择模型。

对空间候选做正向回投：由估计位置和阵列位置重新计算预测方位，与原始观测比较。建议输出：
- 方位回投残差及其统计量。
- 观测覆盖率、漏测、异常点、断段和推断区间。
- 速度/加速度约束检查结果。
- 镜像分支、近似同优解和几何退化警告。

回投误差小只说明与输入观测一致，不证明目标身份正确、距离唯一或空间位置真实。

### 4.6 结果输出与绘图

渲染器只接收标准结果，不访问模型、不重新定位、不读取全局历史目录。

- 方位图：横轴为角度、纵轴为时间，显著标记“非地理轨迹”。
- 空间图：标明坐标单位和原点，使用等比例坐标轴。
- 同身份统一颜色，不同镜像分支用线型区分。
- 缺测、插值、推断连接使用不同样式，不默认跨断段连实线。
- 没有有效点时输出诊断，不生成看似成功的示意轨迹。

默认输出 JSON 与 PNG；调用方也可以仅取结构化结果，自行用网页或桌面图表展示。

## 5. 标准数据结构（建议）

所有数据以普通对象或 JSON 交换，不含页面控件、HTTP 请求对象、模型密钥、数据库连接或绝对文件路径。

### 5.1 Observation

```json
{
  "observation_id": "obs-001",
  "sensor_id": "array-A",
  "time_s": 10.0,
  "bearing_deg": 35.0,
  "bearing_type": "folded_relative",
  "source_ref": "image-A:peak-001"
}
```

补充字段可包括像素位置、测量不确定度和提取诊断。未得到可靠不确定度时保持缺省，不伪造标准差。

### 5.2 GenerationResult

```json
{
  "schema_version": "1.0",
  "status": "success",
  "result_kind": "bearing_time",
  "coordinate_frame": {
    "type": "bearing_time",
    "x_unit": "degree",
    "y_unit": "second"
  },
  "tracks": [
    {
      "identity_id": "target-1",
      "branch_id": "main",
      "points": [
        {"time_s": 10.0, "x": 35.0, "y": 10.0, "origin": "observed"},
        {"time_s": 11.0, "x": 35.5, "y": 11.0, "origin": "observed"}
      ],
      "source_observation_ids": ["obs-001", "obs-002"]
    }
  ],
  "diagnostics": {},
  "warnings": ["仅方位—时间，不代表空间位置"]
}
```

约定：
- status 建议取 success、partial、rejected；成功仅指处理完成，不表示真实准确。
- result_kind 建议取 bearing_time 或 spatial_candidates；空间结果补充原点、轴向及单位。
- origin 建议取 observed、estimated、interpolated，避免把模型估计当直接测量。
- 空间点来源是观测约束时应标为 estimated；observed 仅表示直接使用的观测量。
- 同轨迹点时间严格递增，数值有限；重复时刻、单位不匹配、无来源引用须明确处理。
- 点数、轨迹数、图片尺寸和处理时间设置可配置上限，超限返回明确错误，不静默截断。
- rejected 时 tracks 可为空，必须提供可操作的原因。

## 6. 对外接口设计

首先提供普通函数/库接口，HTTP、命令行和界面均为可选外壳。

```python
# 接口草案，不是已有实现
extract_observations(images, calibration, extractor) -> ObservationSet
associate_observations(observations, options) -> TrackHypotheses
estimate_trajectories(hypotheses, platform_motion, options) -> GenerationResult
validate_result(result, observations, options) -> GenerationResult
render_result(result, render_options) -> RenderedArtifact
```

顶层 generate 用例组合这些步骤。调用者已提供轨迹点时，走“输入校验 → 标准结果 → 绘图”，不重复经过提取或定位。

依赖通过参数或构造函数注入：
- Extractor：传统图像算法、模型适配器或测试替身。
- MotionProvider：按时间查询阵列位置与方向，不依赖特定平台文件格式。
- Renderer：PNG、SVG 或前端数据适配器。
- ArtifactStore：由调用方可选提供，不是算法运行前提。
- ProgressSink：接收进度事件，调用方决定转日志、SSE 或界面通知。

核心实现不得直接读取环境变量、启动外部程序、请求网络或写入固定输出目录。启用云端模型时，由外围适配器负责连接配置、数据发送确认及费用策略；算法层不自动付费重试。

## 7. 建议的最小目录

以下为新模块示例结构，不对应任何现有项目路径：

```text
trajectory_engine/
  contracts.py       # 输入、结果、错误和配置
  calibration.py     # 像素与物理量转换
  extraction.py      # 观测提取接口及本地实现
  association.py     # 片段连接与身份假设
  geometry.py        # 坐标、射线、交会和退化判断
  estimation.py      # 运动拟合与候选生成
  quality.py         # 回投、覆盖和约束检查
  rendering.py       # 标准结果可视化
  pipeline.py        # 用例组合
  adapters/          # 可选模型、文件、HTTP 等外部适配
tests/
  fixtures/
  test_calibration.py
  test_association.py
  test_geometry.py
  test_pipeline.py
```

语言和框架可替换，关键是边界。最小本地版可用 Python + 数值计算库 + 绘图库；图像处理库仅由图片提取能力引入，Web 框架和模型 SDK 不应成为核心模块的必需依赖。

## 8. 分阶段实现

### 第一阶段：点位到结果
实现数据契约、单位/范围校验、JSON 输出和基础绘图。只用手工点位与合成数据验收，完全离线。

完成标准：不用图片、不启动服务、不配置模型也能独立生成轨迹文件；非法输入有明确错误。

### 第二阶段：图片到方位轨迹
实现人工标定、峰值提取、局部关联、断段表达和方位图。增加可选模型提取适配器，但保持相同观测格式。

完成标准：更换提取器不修改关联、定位和渲染代码；提取误差可与人工标注单独比较。

### 第三阶段：双阵空间候选
实现阵列运动查询、时间对齐、分支枚举、几何交会、退化判断和回投检查。

完成标准：已知合成样本可恢复合理候选；近平行、错时、错误配对和镜像歧义不被伪装成唯一正确结果。

### 第四阶段：连续估计与复杂场景
加入运动拟合、跨缺口假设、多目标交叉处理及必要的性能优化。最后才接入页面、任务系统或远程服务。

完成标准：核心测试可以脱离业务系统独立运行；接入工程只负责输入转换、调用和展示。

## 9. 测试与验收思路

分层验收，不只比较最终图片是否“看起来相似”：

| 层级 | 测试样本 | 检查项 |
|---|---|---|
| 标定 | 正反方向轴、边界、非标准裁剪 | 时间/角度映射正确，单位明确 |
| 提取 | 人工标注亮带、网格干扰、低信噪比 | 观测漏检、误检、角度误差 |
| 关联 | 交叉、遮挡、多目标、长缺口 | 身份切换、片段断裂、误连接 |
| 定位 | 已知平台与目标轨迹的合成观测 | 位置误差、候选覆盖、退化拒绝 |
| 质检 | 错配、噪声、错时、镜像 | 能发现不一致，不误称唯一解 |
| 输出 | 空结果、单点、断段、多分支 | JSON 合法，图例和结果语义一致 |
| 独立性 | 假提取器、假运动源、内存输出 | 无网络、无页面、无业务数据库仍能运行 |

先用无噪声合成数据验证几何，再加入噪声、漏测、时间偏差和错误关联。真实位置评测使用独立真值，且不允许真值进入提取、关联或生成流程。

具体误差门限需按采样周期、角分辨率、平台几何和实际业务目标制定，本文不预设未经验证的“准确率”。

## 10. 降低宿主项目依赖的交付原则

1. **以数据契约连接，不以业务类连接**：输入普通观测与平台运动，输出标准轨迹及诊断。
2. **核心不感知运行环境**：不导入宿主 API、页面状态、全局路径或配置对象。
3. **外部能力全部适配**：模型、文件、数据库、界面、日志由外围实现。
4. **算法和绘图分开**：JSON 结果可单独使用，不强制生成图片。
5. **确定性优先**：固定输入与配置尽量得到可复现结果；记录算法/配置版本。
6. **不确定性是结果的一部分**：镜像、断段、弱定位和拒绝原因不能在展示层被抹掉。
7. **先库后服务**：先证明可独立调用和测试，再按实际需求包装 HTTP 或桌面入口。

最终交付应是“一套清晰契约 + 一个独立可调用的生成引擎 + 可选外部适配器 + 离线测试样本”，而不是从某个工程复制大量页面、服务和全局状态。
