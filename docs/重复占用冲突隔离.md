# 模型重复分配观测点的保守恢复

## 问题

模型返回的多个N片段引用了重叠的R候选，导致同一O观测点被声明属于多个独立片段。原校验在第一次冲突处中止整轮。不是导入失败或页面断流，也不能关闭互斥校验来解决。

## 处理规则

- 先解析全部片段并核对编号、提交范围，发现跨片段重复后，从所有提议归属中撤回该点，加入未归属复核。
- 不按顺序挑选归属，不自动合并片段，不自动推断同一目标，不重复占用观测点。
- 保留其余通过既有数值门限的互斥观测；所有结果仍须人工确认。
- 记录duplicate_track_claim警告：观测编号、原始候选编号、模型提议片段及处理说明。原模型正文保持不变。
- 不存在、未提交编号、同片段内部重复、无效版本等仍严格拒绝。失去全部支持点的目标不会补造。
- 已返回且保存的失败回复可通过原工作台“读取已保存回复并本地恢复（免费，不调用模型）”重新验证，不增加calls，不改写attempt原文。

## 实测

只读复核截图对应保存会话20261126_084251_681e35a5：25点中11个存在跨片段重复分配（含O000431）。使用新校验保留3个片段、5条观测，20条未归属；还存在模型同时分配与声明未归属的矛盾。没有写回该用户会话，也没有调用模型。这些结果说明原回复有显著归属冲突，不代表目标识别或最终空间轨迹已成功。

回归覆盖顺序无关、冲突点从所有归属撤回、原始状态/模型正文不变、有效点保留、未知编号拒绝、目标失去支持和免费恢复调用计数。旧的“任何重复整轮失败”断言已替换为“无任何重复占用、冲突点隔离且状态不被原地修改”。

生效需要运行中的后端加载新版Python代码。重启前确认没有仍在运行的付费调用；已有失败回复无需重新发送模型。
