# 轨迹工作台：分阶段实施与版本记录

> 当前 `/incremental` 使用两次独立模型调用：**模型关联 → 人工确认集合（免费）→ 单独授权模型绘图与预测**。主交付为经双阵回投检查的东／北空间候选轨迹；方位—时间图只是可折叠的过渡预览。执行节点以聊天中的可折叠执行过程呈现；资料与校验明细收纳在下拉内容里，不铺开为普通聊天正文。下文旧种子、单轨和后端线性预测章节仅为历史记录，以文末最新说明为准。

## 范围与进度

一期实现单目标假设、单阵列的方位—时间增量预测，独立入口 `/incremental`，主页提供链接，原有识别流程不变。

| 阶段 | 范围 | 状态 |
|---|---|---|
| 一期 | 手选种子、时间调度、文本模型调用、校验、单步绘图、记录 | 已实现；真实模型精度未验证 |
| 二期 | 多目标联合关联、多假设、交叉延迟确认、缺测重关联 | 未实现 |
| 三期 | 双阵关联与空间定位集成、镜像分支、批量评估 | 未实现 |

### 当前完成项与方案调整

- 已落地：高斯批次传递与真实回执、冻结候选及版本、单目标单阵列增量窗口、文本模型调用与问答、预载侧栏、种子/观测/预测绘图、协议校验、有限调用次数、逐轮保存及刷新恢复。
- 部分完成：预测评价只支持新候选与旧预测的同时间残差；早期历史只有数量摘要；数值参考为简单线性外推。没有经过真实模型精度验收，不能称为完整轨迹恢复。
- 未落地：自适应步长、完整折返数值处理、多目标联合分配、有限多假设与延迟确认、合并观测、丢失重关联、新目标发现；本增量链路的双阵空间定位/镜像/回投；自动播放与综合基准评估。
- 总体三阶段不推翻，调整为先完成一期初始化与样本验证，再进入二期交叉，最后接三期空间定位；聊天是产品入口，原表单和绘图是调试验证，不是另一个独立算法。
- 初始化增加免费即时预览：批次/示例载入后，将当前3～5个种子按时间直接连线显示，不创建任务、不调用模型。初始图只显示种子末时刻之前同平台/阵列的候选，没有未来预测虚线；标注“本地点位连线假设”，不是模型预测或已确认同目标轨迹。修改完整有效种子时同步更新图与预载附件，错误编号清除旧图。
- 自动建议不再从首个最低角候选开始贪心接点，改为仅在起始三个时间切片内保留至多32条候选路径，用角速度、角速度变化及needs_review/mixed工程惩罚比较，仍只是未确认假设，不是真实概率。已有人工/缓存种子不静默重写，可点击“重新建议初始3点并显示（免费）”。大角度跳变（>20度工程提示）、混合峰或待复核种子在初始图摘要告警，不直接认定不存在或错误。
- 浏览器 `frontend/tests/check_initial_track.js` 已验证真实批次初始3点即时显示、无任务/模型POST、建议避免截图中的明显跳变、错误种子清图、刷新恢复。该验证不证明真实目标身份或预测精度。

## 使用

### Agent聊天主界面

常驻缓存说明、清除保存按钮和技术调试入口默认收起，不再占据聊天与轨迹之间的主界面；通过页头“更多”打开高级设置。自动保存逻辑不变，清除动作仍需用户明确点击，不因折叠触发。check_advanced_visibility.js验证默认隐藏、可展开/收起及无POST请求。

#### 当前默认：单节点预测调试

默认勾选“单节点预测调试”。一次点击只POST一轮step、至多一次模型调用，成功后保留本轮输入、回复与轨迹并停止，不自动准备下一轮；再次发送按钮禁用。需要继续时用户手动点击“重新准备本轮点位”，该动作只做本地/GET准备，不调用模型。完成标记与任务状态一起在浏览器保存，刷新不会重放请求。

此模式的右侧只直接展示“模型判断与轨迹预测”这一个模型节点，输入校验、上下文准备、回复校验、保存记录四项本地保障收进折叠区，仍实际执行和记录。关闭单节点模式可回到原有逐轮准备与完整节点路径。

浏览器check_single_prediction.js通过本地假网关验证一次POST、一次保存、一个显示的模型节点、四个本地保障步骤、完成后停止及刷新不重发，真实模型调用0次。另修复Windows轮询读文件与原子替换短暂冲突：仅对PermissionError做有限本地文件替换重试，绝不重试模型请求，并补充单元测试。

本次运行检查发现8870仍是旧服务（无preview/execution接口）。原进程未替换；新版另启动在8871，源数据目录和结果文件保留。两个地址的浏览器缓存互相隔离，使用source_result链接载入同一已保存批次即可，不要在两个进程同时推进同一任务。未自动发送真实模型请求。

页面加载时先GET /openapi.json检测preview、execution及selected_times能力，缺失时显示醒目的旧服务提示并禁用预测发送/创建按钮，不再继续调用缺失接口。8870提示可切换已部署的8871入口并携带批次来源；可免费重新检测。404识别会剥离查询参数，区分旧服务缺接口与新版任务不存在，不再将Not Found显示成Agent回答。check_backend_readiness.js已验证旧版拦截、切换8871保持批次、新版就绪，缺失接口请求及POST均为0。

主要交互改为聊天窗口，原“批次、种子、参数、单步协议”收进默认折叠的技术调试区，轨迹图仍为可视化验证。不是只改变按钮名称：问题会进入本轮真实模型请求，并随轮次保存在后端；模型reason和预测作为Agent回答显示。

桌面采用左侧固定可滚动点位栏、右侧聊天与预测图布局，本轮预载只读输入包默认展开在左栏，不再挤占聊天输入区；窄屏改为点位栏在上、聊天在下。仅调整展示位置，不改变预载、调用及未来点隔离逻辑。桌面1440px与移动390px浏览器布局验证通过，无横向溢出；检查脚本为 `frontend/tests/check_point_sidebar.js`。

批次载入后，聊天输入区预载初始种子点位附件，用户在自然语言问题框提问，无需编辑JSON。只读附件可展开查看实际输入包。没有手选种子时，仅从同平台/阵列起始三个时间切片提出邻近候选；明确为待确认假设，不保证同一真实目标，可在调试区修改后重新准备。输入框不会放入整个未来批次。

每次发送推进一轮：首次免费创建本地任务，再免费GET本轮preview；带用户问题、版本和上下文摘要调用原step一次；校验后显示问答、更新轨迹并预载下一轮。只可修改自然语言问题，不可直接篡改原始point_data；后端始终从冻结池重建观测，摘要过期时在调用模型前拒绝。

当前为**轨迹任务型问答**，不是不限主题的通用聊天：每次发送都对应一轮初始化/续接预测，解释问题也随该轮处理。尚未实现单独的不推进轨迹的解释分支、多目标交叉消歧或空间定位。

### 右侧节点执行可视化

宽屏布局为左侧点位、中间聊天/轨迹、最右侧执行路径。中屏执行路径排在聊天下方，窄屏纵向排列。

节点顺序：输入与版本校验 → 本轮点位与上下文准备 → 模型判断与轨迹预测 → 回复与候选引用校验 → 保存本轮轨迹与记录。每个节点由实际服务端代码进入/退出时记录pending/running/completed/failed/skipped和时间、耗时、阶段类型。前端只轮询GET快照（约600ms），不按时间推断完成，不模拟模型内部思考或LangGraph工具调用。

执行记录位于任务目录execution.json（最新快照）及execution_执行编号.json（每次执行独立留存），GET `/api/incremental/sessions/{id}/execution`读取。失败节点标红，下游标未执行；刷新只恢复最后确认记录，不重放付费请求。快照序号用于避免旧轮询响应倒退覆盖新状态；异常不写上游秘密或完整错误正文。

浏览器 `frontend/tests/check_execution_panel.js` 使用本地延时假网关验证右侧布局、模型实际等待期间running、下游pending、成功5节点完成、模型失败后2节点跳过及刷新恢复；真实模型调用0次。API测试在假网关阻塞期间并发读取执行快照，验证不是完成后才补出的假进度。

遇到preview/execution接口404时明确提示重启后端或核对任务编号，不以“Not Found”冒充模型回答。新增接口需要重启服务后使用。

问答记录从后端rounds恢复，输入问题草稿本地保存；刷新只GET核对状态及准备点位，不自动POST模型。费用确认重新勾选。失败/未知结果不自动重试。

右侧问题框默认实际预填“请根据本轮点位判断接续关系，解释依据并预测下一段轨迹。”，不是placeholder；可直接编辑。准备点位不覆盖非空自定义问题，旧缓存空草稿不清空预填文字；问题编辑同步更新左侧输入包。发送只使用右侧实际可见文字，手动清空后会提示填写，不暗中发送默认问题。

### 中文属性与阶段问题模板（当前界面）

#### hull/tow整组勾选

左侧全量点库增加勾选表，按同一批次、平台、精确时间分组：一行分别显示hull和tow候选，可一起选择。一个时间组可能含多峰，分组不等于已确认的双阵目标配对，不按候选顺序强行拉郎配。初始化种子所在3个时间组默认选中并保留，修改起始种子仍在技术调试区完成。

选组后即时同步到聊天发送表，自动模板填入时间组列表、hull/tow候选数和联合参考要求；用户取消非起始组时同步取消。每轮至多16组，同平台续接时间必须晚于已提交时刻。用户明确勾选后续时间可手动推进证据边界至最大选中时间，未选中间组不自动发给模型；不能因此宣称缺口轨迹完整。只浏览菜单仍不改变发送内容。

新任务冻结保存主阵列points及另一阵列companion_points，两者均纳入数据集版本摘要；公开状态不返回未来companion池。聊天通过selected_times提交组选择，免费preview的times参数与step使用同一算法重建原始测量组；上下文selected_time_groups包含实际hull/tow点，且只含选中组。observations旧单点接口继续兼容，但不能与selected_times混传。

模型需联合参考两阵证据，当前协议仍只输出array指定主阵列的方位预测，不输出确认双阵身份或空间坐标；二期联合身份管理与三期空间定位未因此完成。旧任务若未保存另一阵列，前端在付费调用前对比两阵ID和数值并拒绝漏发，提示重新载入批次创建新任务。新增分组参数需重启后端。

相关33项测试通过；浏览器check_group_selection.js用本地假网关验证默认3组、勾选第4组同步发送表及问题、实际两阵数据进入模型上下文与记录，真实模型调用0次。

默认不展示JSON：左侧是点位下拉菜单与中文属性卡，右侧是自然语言问题及可勾选点位表。只展示实际提供的字段：点编号、时间、方位、平台/阵列，以及存在时的质量、相对强度、峰宽、角误差代理。没有航速、空间航向或空间位置就不显示对应项；缺失强度或误差也不显示“未提供”“待估计”占位，聊天回复同样不附加这些空项。

左侧现为**全量候选点库**：下拉菜单包含本批全部候选、全部阵列和时刻，统计区明确区分总点数与本轮选点数。查看后续时刻只更新中文属性卡，不自动加入模型上下文、右侧发送表或当前轨迹图；非本轮点标记“仅点库浏览，不发送”。模型仍按窗口只读取本轮已选点及历史上下文，不因浏览全量点库而获得未来点。浏览器 `check_full_point_catalog.js` 验证427点全部可查、初始发送表仍为3点、查看未来点前后协议输入完全不变、无模型POST。

初始化种子全部选中且不可在发送表中删除；续接轮可勾选本轮候选。表格选项生成内部observations，仍送同一后端校验，不是只做展示。原始JSON仅保留在折叠的“开发协议原始数据”中。历史聊天消息也显示中文点表，Agent回复采用中文决策与时间/方位信息，不直接展示协议对象。

问题默认按阶段自动填充初始化、连续预测、缺测接续、歧义复核模板，结合当前预测时长生成；本轮编辑自然语言会切换为自定义模式。轮次成功完成后自动准备下一阶段模板，不在模型请求执行中悄悄改写已发问题。自定义模式和本轮勾选点会保存并恢复。阶段模板不代表二期多目标消歧已实现。

后端观测协议保持不变：每点candidate_id、t、bearing_deg、array、platform_id，冻结原始值，限制本轮窗口。拒绝越界、重复和改写观测；不自动追加批次外测量。旧版输入框附带的JSON缓存会迁移为自然语言问题＋内部选择，不再默认显示原始数组。

1. 按原方式启动服务，主页进入“纯点位增量预测（一期）”。
2. 推荐在原页面预检或识别完成后点击“将本批高斯点送入预测”，自动载入该结果的高斯测量批次，无需下载再上传。也可导入 `candidate_evidence.json`（images结构）或包含 `candidates` 数组的JSON；可先用页面本地点位示例。导入/创建不调用模型。`platform.json`仅为平台参数，不能作为点位文件。
3. 手选同平台、同阵列、不同时间的3～5个种子编号。点位必须有 `id` 或 `candidate_id`、`t`、`bearing_deg`、`array`（hull/tow）、`platform_id`。时间非负，折叠方位0～180度。
4. 设置切片步长、预测时长、调用次数上限，创建本地任务。仅保留种子所属阵列/平台，不是双阵目标识别。
5. 勾选点位传输与费用确认，执行初始化预测；以后每点一次开放下一窗口并调用模型一次，无图片、无后台自动推进。
6. 不点击即暂停。刷新/重启后凭任务编号加载，不重复调用。导出只含已开放结果，不包含未来池。

种子只是人工轨迹假设，并非真实身份。初始化开放至最后一个种子的时刻；前处理漏检不会自动恢复。

## 接口及约束

| 方法 | 路径 | 行为 |
|---|---|---|
| POST | `/api/incremental/sessions` | `{dataset,seed_ids,stride,horizon,max_calls}`，免费创建 |
| GET | `/api/incremental/sessions/{id}` | 已提交状态和开放候选，无未来池 |
| POST | `/api/incremental/sessions/{id}/step` | `{version,consent:true}`，至多一次模型调用 |
| GET | `/api/incremental/batches/{result_id}` | 将已保存高斯测量导出为点位批次；免费、无图片、无模型调用 |
| GET | `/api/incremental/sessions/{id}/preview` | 免费准备下一轮聊天输入，返回context及context_digest，不修改进度 |

step兼容原参数，新增可选question（至多2000字）与context_digest（SHA256）；Agent聊天入口会携带摘要。模型输出仍受原结构化预测协议校验。

模型连接只用服务端配置。stride为1～8个不同时间切片，horizon大于0、至多600秒，max_calls为1～100；次数不是金额预算。使用90秒模型请求超时，不自动重试。

- 固定候选池和摘要，模型只见近期12个接入点、更早数量、本轮候选、历史预测、线性参考及残差，不见未来点或图片。
- 每时刻最多接入一个点，允许missed/ambiguous/end，后三者不得接入点。模型只能引用本轮开放点。
- 预测须在当前时间之后、时长上限之内，时间递增且角度合法。真实点不被模型改写。
- 初始化保留人工种子，一期不会自动撤销或重选种子。
- 新候选与上一轮**同时间**预测计算残差；未归属候选残差不是确认目标误差。不选最近点当真值；无同时间预测不插值、不报伪精度。
- 历史预测不被后续修正覆盖，模型预测和线性参考分别保存。
- 灰点为开放候选，绿点/实线为接入点及连线估计，蓝虚线为模型预测，橙虚线为线性参考。缺测窗口断线。实线不是实际观测的连续路径。

## 代码与持久化

### 原页面 → 高斯点位批次 → 预测页面

- 原页面的预检、识别、融合绘图逻辑不变。预检或结果含高斯测量文件时显示传递入口；后端最终绘图失败但测量已保存时仍可传递，不必重新付费调用模型。
- 链接为 `/incremental?source_result=结果编号`。预测页从本地批次接口自动读取，展示来源、点数、质量标记和可选种子编号；只载入数据，不自动创建预测任务或调用模型。

## 2026-11-25：先确认目标数据集合，再生成初步轨迹（当前流程 v2）

### 异常点隔离与协议错误分离

- 单个候选的速率或接续残差越界：不放宽门限、不自动接受，转入未归属池并保存拟接入轨迹、具体数值与原因；其他有效集合仍能进入人工确认及后续预测。
- 模型把观测标为歧义，但有效竞争轨迹少于两个：保守转入未归属池，记录归一化提示；不凭空给它造第二个归属，也不自动确认仅剩的一个归属。
- 重复占用、引用未开放候选、版本不符、同轨同阵同时多候选、未经验证跨阵列合并及字段类型错误仍属硬协议错误，不能通过宽松降级绕过。失败不自动重试模型。

### 先选远时刻，再补近时刻

例如人工选择并确认 0、10、20、300 秒，随后又选了 30 秒：

- 30 秒是此前截止时刻300秒之前的历史补点，不作为300秒之后的新观测追加。
- 从30秒重新复核，保留0／10／20秒此前片段，将30秒和已提交的300秒点重新比较；300秒的旧归属仅是可修订假设，不强制接续。
- 先显示修订数据集合，等待再次确认；确认前显示旧图、保留旧预测账本。
- 确认后生成新的后验修订。若300秒仍属于该轨迹，该轨迹的未来预测仍从最后实际观测之后开始，不把包含300秒信息的计算包装为当时30秒已知的预测。
- 不补造20～300秒的观测或实线连续路径。若所说“相近”只是方位接近，但时间仍晚于当前截止时刻，则按正常新增观测比较，不因图上距离近就当作历史补点。
- 真实观测与系统预测点始终分开；生成的预测点不会自动变为后续关联的真实测量。起始片段仍由关联后的各轨迹分别确定，不恢复自动固定三个种子点。

验证：本轮相关后端回归104项通过；浏览器假网关检查了聊天集合表、确认前无新图／预测、确认后本地出图、确认不二次调用模型、待确认刷新恢复、旧图保留、历史复核和打回。另新增“0／10／20／300秒后补30秒”的数值回放，以及异常点不阻断有效轨迹的检查。未运行真实付费模型精度验收。

补充时间边界：新预测时间必须晚于本轮已知观测的最大时刻。若某轨迹只有很早的历史且原预测窗口已过期，只保留该轨迹与旧预测并说明原因，不把旧时段再标成当前未来预测；其他具备近期有效证据的轨迹仍可独立预测。
