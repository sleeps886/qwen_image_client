# 导入区一直灰色与虚拟压缩目录拖拽

## 现象与定位

截图中没有加载数据，而导入框与选择文件按钮禁用、表单显示“正在处理”。代码中初始化被纳入全局 busy 锁，原有网络请求、IndexedDB打开及事务均没有等待上限，任何一个未完成都会阻止导入。未取得实际 File 的拖拽也会被静默忽略。

截图还显示资源管理器“压缩大小”列，可能是在外层压缩包的虚拟目录内。没有直接读取用户浏览器现场，不能仅凭截图断定具体是哪一个等待项或压缩目录行为造成的。

## 修改

- 普通JSON接口读取15秒、提交30秒超时；导入解析及响应读取30秒超时，AbortController取消页面等待。付费SSE调用没有套用该短超时，也不自动重试。
- 健康检查与接口协议检查并行，失败后仍允许独立导入，但保持付费发送禁用。
- IndexedDB打开10秒、事务15秒超时；不清库、不删除旧文件。超时/旧标签页占用时显示原因，结束busy并允许重试。
- 初始化期间、初始化失败、空拖拽、忙时拒绝导入均显示明确状态，不再静默无反应。
- 提示从外层ZIP内操作时先解压到普通目录，再拖入内部轨迹ZIP或选择文件。轨迹ZIP本身仍由后端读取，不要求用户解压每个轨迹包。

## 验证

- 浏览器故障注入：接口永不响应、文件库首次打开永不完成；真实等待到超时，导入按钮恢复，错误可见，付费发送禁用。
- 空DataTransfer拖拽显示压缩目录提示。
- 同一故障恢复页面重试实际三个ZIP，完整导入966点，无模型发送。
- 正常三个ZIP导入、20点抽样、删会话保留文件、刷新保留、导出、重新打开回归通过。
- 独立文件库v1迁移、原始数据保留、删除墓碑及并发导入回归通过。
- Node抽样与邻域选点两组测试、JS语法检查、git diff --check通过。

测试使用隔离服务和新浏览器配置，未修改用户已有会话/文件库。刷新页面即可加载新版脚本；如果其他旧工作台标签页占用文件库，先关闭或刷新它们，不要清除浏览器数据。
