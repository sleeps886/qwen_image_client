# 单平台多目标：模型融合优化与真实对照

日期：2026-11-20。状态：已改善漏身份与无依据改坐标问题，**未通过完整目标识别和唯一位置精度验收**。

## 需求与实现

| 用户需求 | 实际修改 | 验证 |
|---|---|---|
| 暂停多平台分析 | 删除多平台匹配模块及网页平台编号选择；图片输入和反演任务拒绝多平台JSON，保留单平台旧版DB_STEP兼容 | 单平台/多平台拒绝/重复阵列/平台名不匹配测试 |
| 三类图生成正常，重点改模型判断 | 不改生成器、不重写高斯/本地反演算法；三类六图保持，逐身份增加实际双阵测量编号、时间、角度与误差代理 | 模型输入保存在各轮input.json；没有目标标签、truth或meta路径 |
| 不再只剩一个目标 | 提示词逐身份决策，区分关联身份与镜像；增加漏身份、未说明身份、未保留镜像的结构化审计 | 截图同样本从旧版1个输出身份，经v2的3个到v3/v4的4个 |
| 不凭外形编造空间曲线 | 说明BTR方位历程不等于空间轨迹；核实生成器没有海面反射/多路径机制；位置信息弱不是目标不存在 | 同样本v2模型坐标回投RMSE约41.106°，v3/v4约0.371°/0.372° |
| 检查模型坐标，不只检查后端候选 | 新增model_final_quality.json，按模型坐标插值到测量时刻，分别重投影到hull/tow并比较来源测量 | 已测试真实坐标一致、任意平移不一致；不修改模型坐标、不自动补候选 |

当前融合提示词版本：`single_platform_fusion_v4`。模型最终坐标仍来自真实模型回复；后端不使用评测真值挑选或覆盖坐标。默认生产调用仍是一次，无自动付费重试。

- 截图同样本：来源运行`20261120_092234_a39cdee1`；原始图片以已保存SHA256回查生成器导出，未猜测配套图片。
- 新生成2目标/5目标样本：调用用户原工具`btr_gui_server.run_simulation`与`gen_train_ds.build_payload`，固定种子20261120/20261121。生成器源码未修改。
- 每个新样本先做本地数值反演，再向模型发送双阵原图、高斯测量叠加图、主候选及镜像候选，以及平台/测量/候选坐标文本。

下表“1km内匹配”按一对一匹配，若保留多个镜像，取最佳分支。**这是离线真值辅助下界，不代表程序已正确消歧，更不代表每个预测身份都是真目标。** 回投误差是模型坐标对来源观测的加权角度RMSE，不是真实位置误差。

截图同样本v4的一对一匹配分支RMSE约69、174、4、275米，但所有竞争镜像仍在输出，不能宣称唯一轨迹正确。新5目标样本仍有两个目标最佳分支约3.20km和1.75km偏差。新2目标样本的多余关联身份在v3仍存在。

## 已知剩余问题和下一步

1. **额外身份**：2目标样本数值层形成3个关联身份，模型也保留3个；需要改进交叉处双阵配对与跨时段身份归并，不能根据已知标签硬删一个。
2. **弱视差与侧别**：低角度回投误差仍可能对应公里级位置偏差；保留竞争分支，不以视觉偏好宣称唯一位置。
3. **位置/时段覆盖**：当前每条模型轨迹采样有限，评测只针对与真值可见时段重叠的点，未验收全时段完整恢复。
4. **泛化**：3个样本、8次调用仅是有限开发对照，不是大样本盲测。v3在5目标样本的位置匹配曾退化，不能用截图样本进步掩盖这一点。

## 主图与镜像视图的后续展示修正

原模型融合主图把每个身份的多个镜像分支一起绘制，4个身份可能出现8条线，且额外候选扩大坐标范围，容易误认为新增目标或轨迹完全不同。现在 `estimated_track.png` 按模型输出顺序展示每个身份的一组代表侧别（保留该侧别的所有片段），不读取参考真值、不声称侧别正确；`model_mirror_candidates.png` 单独保存全部模型分支，`tracks.json` 仍保留所有模型坐标。后端数值镜像仍使用另一个文件 `mirror_candidates.png`，两者明确区分。颜色按模型身份分组，不与仿真参考的真实目标ID做隐式对应。
