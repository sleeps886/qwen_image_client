# 工作台50组快照批次方案与实现

## 固定协议
- 原逐组模式保留。新模式 `batch-snapshot-v1` 每批默认50组，每组是给定的hull＋tow双阵容器，支持不足50组的末批。
- 批内最多50路独立模型请求，共用不可变批前state快照及本批背景；批间顺序推进，不向模型暴露后续批次观测。
- 单组返回只是归属建议，包括已有目标、新目标或待定。建议中的新目标名不直接等同全局ID。
- 每批再调用1次归并模型，综合全部观测和建议决定全局目标编号、竞争及明确的历史修订。没有本地距离/峰宽规则代替模型分目标。
- N编号新目标由应用生成稳定B编号；已有编号保持稳定。应用仅校验版本、引用、覆盖和重复，不自行选择归属。
- 483组对应10批，最多493次请求；不是10次调用，也没有首组免费初始化。准备免费、实际发送需显式授权。

## 状态与快照
- 沿用当前会话state及SQLite逐组运行表；新增 `batch_snapshots` 表，按run、批次及状态版本保存已处理观测、归属与导航配置。
- 批内并行请求不写轨迹。已返回建议和原文逐条持久化，界面显示返回数；批内观测可显示为待校验点，不冒充已归并轨迹。
- 模型归并校验通过后，工作状态与该批快照在同一SQLite事务发布。已确认主state不被自动覆盖，仍须最后点击确认。
- 下一批读取上一批工作快照；快照内含观测、已有目标和有序片段，不只是画出来的折线。平台导航与未选择镜像分支的交点候选一同提供给模型。
- 原始数据完整保留；不受旧80条疑点复核或160组本地暂接降级控制。新模式只根据模型归属生成边，不使用本地自动分目标。

## 中段补点与末尾接续
- 归属后按观测时间排序。新增中段观测会替换原前后边；末尾观测向后接续。
- 归并模型可用 `revisions` 明确引用已知历史观测，撤回/改接归属；不得修改未提供的未来观测。
- 撤回边和历史归属变化留档，同一工作目标的线/点同色实线。几何镜像仍是可切换的显示假设，不宣称唯一位置。

## 费用与故障
- **更新：**已授权的 `retry-v1` 队列启用有界输出格式重试，旧队列仍保持不自动重试。具体预算、输入紧凑表、失败环节恢复及实测见 `batch-output-retry-v1.md`；下列“不自动重试”的早期记录不适用于已明确授权的新格式重试策略。
- 并发数与批大小分别配置（1–50），不保证上游允许50并发。
- 先检查整队列及当前批预算；每次发出请求前持久记账，明确区分调用次数与实际账单金额。
- 网络未知、限流或无效回复保留已收原文，停止后续批次，不自动重试或用本地结果填空。
- 已完整保存但字段校验失败的批内建议可免费复核；通过后下一步只进行新的模型归并，不能重发原50次请求。归并本身失败不通过旧回复自动重试。
- 暂停停止后续批次，当前已启动请求/归并继续完成；关闭页面不取消任务。重启中断的running任务标为未知，不自动续费恢复。
- 已有会话可显式点击“应用预算到现有会话”，修改累计调用上限；不发送模型，不修改旧队列授权。活动队列未结束时禁止改预算。

## 工作台使用
新建、导入数据后的默认模式为50组快照批次；用户手动选择的模式随会话保存。已经准备或授权的旧逐组队列保持原模式，不能靠修改预算改变执行方式。

若界面锁定旧模式，会明确显示“当前锁定的是旧逐组队列”，可点击“结束旧队列并切换50组模式（免费）”。操作必须确认：旧队列未确认的暂定更新不采纳，原始数据、已确认历史和旧原文保留，不调用模型。

1. 结束旧队列（确认或明确放弃），保留原始文件。也可新建会话后打开旧文件。
2. 全选数据，执行模式选择“50组快照批次”，每批50、并发50。
3. 483组设置队列调用上限493；旧会话剩余不足时明确应用预算。
4. 免费准备，核对调用上限及模型；勾选费用授权后执行下一批或连续按批执行。
5. 右侧检查点线；执行记录可展开单组建议/模型归并原文和实际输入、复制上下文、下载批次快照。
6. 最后人工核对并确认更新。目标归属假设、条件空间交点与真正的未来预测仍分别标注。
