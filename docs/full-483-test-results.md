# 三个ZIP的483组全量测试（2026-11-26）

## 范围
使用用户提供的 `btr_target_001 (2).zip`、002、003。仅读取观测和平台配置，不用真值给目标归属打标签。隔离临时状态，未修改用户会话，真实模型调用0次。

## 实测结果
1. 浏览器导入966条观测，全选483组双阵成功，来源预览正常。
2. 默认20次预算阻止准备，提示需要482次；输入框最大99，混合会话API预算最大100，因此当前网页不能直接执行483组。
3. 仅在隔离测试服务层给482次测试预算，使用明确将可编辑观测保留为未归属的离线网关：成功处理42组、41次模拟调用；第43组准备时，未归属复核范围82条超过默认80，停止于模型调用之前。不是上游超时，不应自动丢掉历史以继续。
4. 上述测试约23.05秒，队列准备约0.0025秒。未发现未来观测泄漏或已处理组静默丢失；暂定结果没有绕过人工确认写成正式轨迹。
5. 独立构造483组几何/渲染压力夹具（不是Agent完成结果）：483组均有记录，475组能放置条件交点，8组无可用位置。无位置不等于丢失数据。
6. 超过160个可用组时，本地暂接按现有代码降级；在无Agent边的压力夹具中，连线数为0。因此即使解除预算限制，也不能保证完整暂接图。

## 结论
当前版本**未通过483组完整逐组关联与连线验收**。显示全选成功不等于执行完毕；压力测试不能证明真实模型能分出三条轨迹。

## 后续修复要求
- 一致调整混合会话、网页预算配置和校验，仍须用户显式授权，不提高旧队列已授权预算。
- 将未归属复核改为可追溯的有界分区/分页任务，保持历史存储，不截断后冒称全量联合判断。
- 超过160组采用局部增量重算，保留旧边及修订记录，避免整个图突然降级成散点。
- 修复后补483组连续执行、暂停恢复、峰值延时/状态大小及完整图表回归；真实模型准确率另做有预算的评估。
