# 增量轨迹v2：使用、接口和验收

**当前用户入口已纠正为原`/incremental`工作台，不再要求另开`/live`。** 实际操作和兼容边界见[工作台整合修正](工作台整合修正.md)。本文件保留实验v2 API/诊断视图的技术验收记录；普通`/live`已重定向，诊断脚本使用`/live?diagnostic=1`。

日期：2026-11-25。工程阶段M0～M4已形成可执行入口；不承诺任意方位唯一定位，不声称真实模型准确率已验证。

## 1. 启用与兼容

- 等当前真实任务结束后重启后端，打开`http://127.0.0.1:8870/live`，或从旧轨迹工作台侧栏进入“实时增量接入v2”。本次开发没有重启用户生产服务。
- 新账本为`outputs/live_tracking/ledger.sqlite3`，SQLite WAL，单进程部署。没有新增云依赖，也没有读取或复制认证配置到会话。
- 旧`/incremental`工作流和JSON仍可使用。选择新入口是显式版本切换，不是自动升级旧会话。
- 删除旧文件库条目不会删除独立v2账本。撤回归属不删除测量。导出备份、保留与物理清除需要单独操作；本批未执行任何用户数据删除。
- 首次启动未使用v2时无需创建账本。已有账本启动时只恢复任务状态，不恢复付费发送。

## 2. 正常流程

1. 新建空会话，明确相对秒/采集时钟的`timeline_id`；不同场景或未知时钟使用独立会话，不能仅凭平台配置相同合并时间轴。
2. 填写来源ID。追加单点JSON、数组，或拖入ZIP/JSON。原始编号在“会话＋来源”范围内去重；相同编号不同值隔离为冲突，原值不覆盖。
3. 查看逐项回执及隔离原因。接入成功响应丢失时，可用原幂等键重发；不要为了重发修改来源/键。界面提供重发原请求按钮。
4. 全选、手选、按点随机、可选同步组或事件窗口选择。数据分页仅用于展示，不裁剪分析。实时追加不经过抽样。
5. 免费准备：查看真实点数、明确包含的历史、知识截止、能力、候选覆盖和迟到影响范围。原始测量、平台、时间不能被模型修改。
6. 对此快照单独勾选授权，发送一次关联。执行时仍可追加点；新点进入待分析队列，不混入旧快照。
7. 读取完整正文与提案，免费采用或填写原因打回。采用时检查投影版本；配置或另一决定改变基础时，旧提案保留为stale，不覆盖新状态。
8. 若需预测，另行指定知识序号、事件起点、时长和用途，免费准备并独立授权。可切换预测版本；真实点与生成曲线分层。

接入示例：

```json
{
  "idempotency_key": "ingest-01",
  "source_id": "sensor-A",
  "timeline_id": "relative-seconds-01",
  "observations": [
    {"source_observation_id":"raw-11","event_time":37,"platform_id":"A","array":"hull","bearing_deg":104.6}
  ]
}
```

单点就是长度1数组；`candidate_id/t`旧字段也可规范化。编号、时间、平台、阵列、折叠方位必须有效。单阵/异步不是错误；同批无效行不吞掉合法行。JSON整体损坏或请求资源超限不能宣称已接收。

## 3. 时间、版本及证据边界

- `event_time`是观测发生时间；`received_at/receipt_seq`由服务器生成。配置和人工采用也在知识顺序中留事件，因此序号不是点数。
- 因果预测同时过滤`receipt_seq <= knowledge_cutoff_seq`及`event_time <= forecast_origin_time`；使用该知识截止之前已获知的配置。
- 后来采用的投影如含超出范围的点，或其决定发生在知识截止之后，会从历史预测上下文排除，不能“只删未来点却保留未来推导身份”。
- 若当时已存在且范围兼容的旧采用版本，则从投影历史中读取该已知版本；不因排除当前未来投影而丢弃当时真正可用的历史身份支持。
- 观测版本只因新增有效测量推进；人工决定/配置推进独立投影版本。新点追加不使旧快照自动失效，也不被旧结果覆盖。
- 默认关联准备纳入全部有效观测；显式选择时还明确纳入已采用投影的历史范围（包括其待证据/待决点），不在网关隐藏补点或裁点。
- 同步定义为同平台、严格同事件时刻，非目标配对。当前同步数值路径的至少5时刻要求只属于其留出算法，不是入口门槛。
- 默认候选窗口8个独立时刻、步长4，每窗口预算6，随机种子19；均是可见的实验参数/版本，不是已标定物理常数。候选预算不删原始观测。
- 不确定依赖的迟到回放扩大到完整快照；不会为节省计算假称已证明局部无影响。云调用仍需明确范围与授权。

## 4. 任务与异常

| 状态 | 行为 |
|---|---|
| authorized / dispatching / running | 单次发送意图持久化；新点接入可继续 |
| awaiting_review | 完整契约已本地校验，等待人工采用；不是物理身份真值 |
| invalid_reply / output_truncated | 原文保留，不修补编号，不自动重发 |
| unknown | 已进入发送窗口但结果未知，需核对供应商记录，可能已计费 |
| failed＋InterruptedBeforeSend | 尚未进入发送窗口时进程停止，已知未发送，需重新准备/授权 |
| stale | 配置或投影已变；旧结果保留、不覆盖当前 |
| completed / rejected | 已完成采用、预测发布或明确打回 |

刷新、GET任务、SSE重连和导出不会发送模型。事件流支持`after_seq`及`Last-Event-ID`。中断可保留正文并只读重连。手动重跑需`rerun_of`和费用风险确认；若配置改变，请先重新免费准备，再明确重跑旧失败任务。没有供应商幂等支持时不承诺外部严格exactly-once或绝对不重复计费。

正文以追加事件保存，任务摘要不重复保存每个token时的全文，避免长流持续重写全文的平方级写入。正文解析资源边界4百万字符，超过时保留已收到部分并标记未完成，不把它当成功，不裁剪授权输入。

## 5. 实际接口

统一前缀：`/api/incremental/live-sessions`。

| 方法/后缀 | 功能 |
|---|---|
| GET/POST 前缀 | 列表/创建空会话 |
| POST `/migrate` | 显式复制旧观测，可传`legacy_history`存档，保留旧编号映射；不采用旧结论 |
| GET `/{sid}` | 观测/投影版本、接收统计、待分析队列、任务/预测摘要 |
| GET/POST `/{sid}/observations` | 接收单点/批次，或按`after_seq`读取有效事实 |
| POST `/{sid}/configuration` | 配置版本变更，带`expected_state_revision` |
| POST `/{sid}/prepare` | 免费冻结关联快照 |
| GET `/{sid}/snapshots/{snapshot_id}` | 只读快照 |
| POST `/{sid}/analyses` | 明确授权一次关联 |
| GET `/{sid}/analyses/{rid}` | 包含实际完整已接收正文的只读任务 |
| GET `/{sid}/analyses/{rid}/events` | 序号重连事件流，预测任务也使用同一只读任务入口 |
| POST `/{sid}/analyses/{rid}/review` | 采用/打回，投影版本CAS |
| POST `/{sid}/retractions` | 带版本、稳定ID及原因撤回归属，不删测量/旧结果 |
| POST `/{sid}/predictions/prepare` | 免费冻结因果预测或事后重建 |
| POST `/{sid}/predictions` | 独立授权预测 |
| GET `/{sid}/predictions/{prediction_id}` | 只读预测版本 |
| GET `/{sid}/export` | 原始接收审计、有效事实、版本、快照、完整正文与事件导出 |

模型输出契约为`association-compact-v2`；预测为`bearing-prediction-v1`。无损输入表为`live-input-table-v1`，模型只引用快照内行号/候选，不接收来源文件名、目标标签、参考真值或旧存档。

SQLite物理表为`live_sessions/observations/receipts/requests/entities/run_events`。`entities.kind`区分配置、快照、任务、投影、预测和旧存档；不是设计草案里所有逻辑实体各建一张表。
