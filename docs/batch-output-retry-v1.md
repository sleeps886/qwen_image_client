# 批次输出稳定性与失败环节重试 v1

## 已实现
- 新队列使用 `batch-compact-v1`。输出只包含归属及固定 `reason_code`，禁止自由文本理由。协议由本地严格校验，不声称上游原生支持JSON Schema。
- 观测合并为一张无损表，历史/当前组通过原样ID引用；导航只传一份，几何候选与单组建议表格化。无数据下采样、补值或截断历史；可反解验证每个原始字段。
- 某组返回非法JSON/无效枚举等，只重试该组；归并返回非法JSON/缺组/越界引用等，只重试归并。成功单组不会重发。
- 正常“未归属/待定”是有效结果，不触发重试；HTTP异常或超时标为结果未知，可能已计费，不自动重试。
- 默认每环节最多额外2次（总尝试最多3次）；退避约2秒、5秒并加抖动。重试最多5路，仍受批内总并发上限约束。
- 重试固定同一快照、数据与模型绑定；仅附结构错误代码，不把上次乱码正文喂回模型。
- 每次调用前持久记账，保留所有尝试的原文、状态、用量、输入哈希与错误。模型结果校验通过才原子发布快照，不用残缺JSON局部结果冒充完整归并。
- 暂停在重试等待期间生效时，不再发起该次重试。状态版本变化阻止旧结果和旧重试请求写入。

## 预算与界面
- 自动重试需要在免费准备中明确列出次数及预留，并随发送同意一并授权。旧队列策略保持不变，不自动涨预算或恢复失败请求。
- 483组正常最多493次；全队列预留20次重试，建议总上限513次。20是整队列预留，不是每组20次；额度用尽即停。
- 新界面显示重试开关、每环节次数、全队列重试预算、已用次数与当前阶段。
- 旧失败任务点击“准备失败环节重试（免费，需重新授权）”，明确确认总上限后，再勾选费用授权，点击“仅恢复失败环节”。免费准备不调用模型，成功回复和此前快照保留。
- 旧的“复核保存回复”只做可重新校验的完整单组回复，不修补残缺归并正文。

## 实测
- 使用用户会话 `20261126_160221_e6c775eb` 的隔离副本。前三批150组已完成，第4批50条单组均成功、归并正文出现无关词串并缺少闭合。
- 复用50条建议，只新增1次真实归并请求（测试授权上限2次），成功从150组推进到200组，保存第4份快照，保持3个目标假设。
- 前三份快照原文不变，生产会话未修改，不重复任何单组判断。
- 本批基础输入从197342字符减少至77933字符，约60.51%；反解结果与压缩前一致。该数字是字符数，不冒充token数量。
- 报告：`output/supplied-zip-test/compact-retry-20261126_163519-fd7627/report.json`。
- 显示覆盖核对：200组均有记录，193组有条件空间交点，7组无法定位，不是观测丢失。后验来源对照仍发现1组跨来源归属，已存在于原150组历史中，需继续复核；不能仅凭“3个目标”宣称轨迹准确，也不按来源标签替模型改归属。
- 本地故障注入覆盖单组重试、归并重试、正常待定、未知结果不重试、次数/全局预算、暂停、状态变化、重复调度和旧队列显式授权。
- 浏览器回归验证单组/归并两种重试、计数展示、旧失败任务免费准备与重新授权、成功结果复用，无运行时错误。
- 本轮相关后端回归79项通过，另9个子测试通过；Node预检/几何测试通过。上游原生JSON Schema未假定可用，约束由精简协议及本地严格校验保证。

## 边界
本修订解决输出格式和恢复机制，不保证模型目标识别准确；200组验证不等于483组全部真实验收完成。服务返回未知结果时不会自行重复收费请求。
