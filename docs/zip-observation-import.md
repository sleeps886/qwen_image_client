# 轨迹包拖入导入

轨迹工作台的数据点导入区域支持直接拖入、或选择 ZIP / JSON，一次最多16个文件。

- ZIP需包含唯一的 `observations.json`，可位于 `input/` 等子目录；优先使用其中的 `platform_config`，否则读取同目录的 `platform.json`。
- 不读取包内 `reference.json`、图片、说明书或清单，不把真值用于关联预测。
- 一次多选/拖入多个包会合并成一份观测文件，按来源文件建立浏览分组，重命名观测编号避免冲突。分组不是模型身份答案。
- 多文件平台配置必须一致；不一致或部分缺失时拒绝合并，请分别导入。
- 导入后下方立即显示分组、时间行和可选观测。M0 更新后不再按缺阵或不同步排除有效观测；双阵时刻仅作诊断统计，不认定目标配对。文件库保留全部原始观测，导出为JSON。旧过滤快照的恢复边界见[实施进度](实施进度-增量轨迹.md)。
- 导入不调用模型；解析失败保留现有工作区。
- 单文件上限16MiB，总上传上限20MiB；ZIP最多2048条目，声明展开总量上限128MiB。仅读入内存，不向磁盘解压，拒绝不安全路径、加密文件、损坏压缩包和不合法观测。

验证：`python -m pytest backend/tests/test_observation_import.py -q`。浏览器回归脚本为 `frontend/tests/check_zip_observation_import.js`，依赖现有隔离测试服务及生成器测试ZIP样本。

## 独立导入平台与字段展示

“平台配置”区域可单独选择 `input/platform.json`，也接受平台数组或含 `platform_config` 的JSON。单个平台文件上限100KB。

导入后每个平台显示一张只读字段卡：名称、经度、纬度、航向、航速、舷侧阵和拖曳阵x/y偏移。存在合法十六进制颜色时展示色块，否则显示“未提供”，不编造颜色。

可先导入平台，再导入无自带平台配置的观测。待应用平台与当前会话均由浏览器保存。平台名称必须覆盖观测中的平台编号；失败不替换现有配置。已有后端分析会话时，导入新平台另建会话并保留旧结果及原点位选择，不直接修改旧分析的导航依据。导入只做本地解析与显示，不调用模型。

接口：`POST /api/incremental/import-platform`，multipart字段为 `file`。
测试：`backend/tests/test_platform_import.py`、`frontend/tests/check_platform_import.js`。

## 删除文件联动清空

删除当前打开的数据文件后，自动清空当前观测列表、分组、已选点、图中观测、平台显示和当前恢复指针；刷新不会自动恢复。删除其他文件或取消删除，不影响当前浏览数据。历史会话与后端分析结果保留，需要时可主动打开历史会话；删除文件不会调用后端删除或模型接口。来源链接中的 `source_result` 参数同步移除，已标记删除的来源不再自动导入。

回归脚本：`frontend/tests/check_delete_active_file.js`、`frontend/tests/check_point_files.js`。

## 大量点位全选后的提交（当前行为：不设固定点数上限）

混合观测工作台已取消每轮256/4096点上限，并取消混合数据集与高斯观测导出的20000点上限。至少选择1个真实有效点；编号、数值、平台与阵列格式校验保留。共享的旧版单阵逐轮预测流程保留原有保护，不影响当前混合工作台。

预测专用文本网关与混合输入生成不再设置本地提示词字符上限，也不因超长缩减已生成的接续参考；所有选中观测完整保留，不截断、不自动拆成多次付费调用。普通图片识别仍保持原有提示词限制。

前端从后端OpenAPI读取点数契约：新版未声明maxItems时显示“不设观测点数量上限”；若连接旧版受限后端，明确提示重启后端并刷新。处理中按钮显示等待状态。免费准备不调用模型，付费发送仍须显式授权。

不设固定点数上限不等于无限处理能力。HTTP请求、上传/解压文件和响应大小保护、机器内存/处理时间，以及模型供应商上下文和额度等限制仍然存在。大输入可能增加耗时和费用，也可能被供应商拒绝；失败不自动重试。

验证：1224点真实本地准备与隔离假网关轮次；5000点准备和浏览器模拟发送；20002点混合任务创建；超过100万字符的离线请求组装。未调用真实付费模型。

相关测试：`backend/tests/test_large_mixed_selection.py`、`frontend/tests/check_large_mixed_selection.js`。

## 流式连接断开与 CancelledError

2026-11-25 检查已有执行记录：本地模型流标记为 `cancelled_locally`，关联节点在约39秒时收到 `CancelledError`，保存了部分正文但没有完整结果；任务为 `call_unknown`。这与点数格式校验失败不同。现有记录不能确定取消最初由页面、网络还是服务生命周期触发，不能断言是模型拒绝或固定超时。

混合关联/绘图调用现与HTTP观察连接分离：浏览器断开仅停止观察，不取消原模型任务；任务继续使用同一次网关调用完成校验和保存，并在结束时释放锁与运行槽位。每10秒发送SSE保活注释，不展示供应商私有推理。页面增加“刷新任务状态（免费，不重新调用模型）”，只做GET读取。执行中不允许重复发送或重新准备失败轮次。

服务停止、进程崩溃或真正上游异常仍可能导致结果未知；后台任务不跨服务重启存活，也不自动重试。旧的已取消调用不能靠此修复恢复完整正文，需要先核对服务记录和计费，再自行决定是否重新授权。手动恢复本轮输入也已取消遗留256点上限，免费准备本身不增加模型调用次数。

验证：真实ASGI断连、观察端取消、空闲保活、未启动响应释放锁、后台任务被真正取消后保持unknown，以及前端GET刷新状态，均使用隔离假网关，不调用真实模型。测试：`backend/tests/test_detached_mixed_stream.py`、`frontend/tests/check_running_task_refresh.js`。

## 填数量后随机小间隔选点

数据浏览按钮下新增“要选多少个点”和“随机小间隔选点”。填写的是抽取点数，不是秒数，也不是新增上限。例如选择“全部候选”，输入100，会把当前1224点选择替换为100个真实观测。

按时间、平台、阵列和编号排序，在近似等间隔的索引位置周围做小幅随机扰动（位置幅度约为名义间隔的±20%）。选取2点及以上时保留排序首尾；选择1点时随机取1点。原数据时间分布可能不均匀，因此不保证等秒间隔。不伪造坐标、不改变观测值、不重复选点。只有一个可选组合时（如全选、2点保留首尾）重复点击结果可能相同。

操作替换当前浏览分组内的选择，其他分组的已选点保留，所以全局已选数可能大于填写数。输入空值、非正整数或超过当前分组可用数时提示错误并保留原选择。原始文件及完整数据不被裁剪，数量和已选编号随会话保存。处理中或等待集合确认时禁用抽样，不自动调用模型，也不自动勾选付费授权。

验证：`node --test frontend/tests/test_point_sampling.cjs`，以及 `frontend/tests/check_point_sampling.js`。已在1224点合成数据上验证抽取100点、重复抽取变化、分组范围、首尾保留、错误输入不改选择、原始点位不变和刷新恢复。

## 完整流式正文展示

修复执行节点只有最后一条reason/summary跳动：旧版前端仅截取最后一个说明字段，且最多显示2000字符；新界面使用独立的“模型正文 · 完整流式输出”区域持续追加所有正文delta，包括结构化JSON，不再用后一个理由覆盖前文。

正文区域不随500ms执行节点轮询重建。默认跟随底部；向上滚动阅读时不强制拉回。执行时默认展开当前过程，接收完后不因状态变化主动收起有正文的过程，用户仍可自行折叠。正文与状态按执行编号保存，完成后保留；中断时保留已接收部分并明确标记，不把部分文本当作有效集合。刷新恢复的是已保存内容，未收到或未保存的内容不能补造。

仅展示供应商正文delta，不显示私有推理字段。查看、展开和刷新保存内容不重新调用模型。

验证：400点隔离假网关的实际SSE逐块对照，超过2000字符完整一致，滚动位置及DOM不被轮询重置，完成与刷新后仍保留正文。测试脚本：`frontend/tests/check_full_stream_body.js`。当前正在执行旧版页面调用时，建议等调用结束后再刷新，不为验证显示而重新发起付费调用。

## 模型返回后的编号/占用校验失败

对已保存的一轮100点回复做离线检查：片段N3引用了不在数据集中的 `O00011`；另一个目标假设H5引用三个片段，超出当前目标协议的1～2片段约定。不能据此自动补零、替换点位或放宽占用规则，也不能把模型的文字判断直接作为已确认结果。

校验报错现在区分“编号不存在”“编号未在本轮提交”“重复占用”，对合法协议形状的编号指出具体位置和冲突归属；任意非协议文本不直接回显。提示词要求原样复制编号（包括前导零），但此提示不保证模型绝不再犯错。

SSE错误新增 `reply_validation_failed` / `model_stream_failed` 分类。正文已返回但校验失败时显示“模型正文已返回，但校验未通过”，不再误报“页面流已中断”。对旧浏览器快照，也会根据失败的validate/plot_validation节点识别校验失败。原始正文保留，不自动修正或重新调用模型。

测试：`backend/tests/test_mixed_reference_diagnostics.py`、`backend/tests/test_detached_mixed_stream.py`、`frontend/tests/check_validation_stream_status.js`。检查和测试均为离线/隔离执行，未重新请求真实模型。
