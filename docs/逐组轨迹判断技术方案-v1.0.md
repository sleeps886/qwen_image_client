# 逐组轨迹判断技术方案 v1.0（冻结基线）

状态：已由用户确认并要求开始实施。此文档是需求与验收基线，不代表全部能力已实现。
后续变更另记版本与原因，不以实现方便为由悄悄恢复整批模型判断。

## 1. 确认范围

- 一组hull＋tow是一个输入单元，原始两条观测独立保存。单阵输入保留，不补造。
- 单组提交执行一步；混合批次进入队列再逐组执行，两者共用逐组引擎。
- 两者都能接续已有轨迹。处理数量不等于目标数量，不预设三个目标。
- 每步只新增当前一组，参考已处理历史、既有轨迹及相关待决观测；未处理队列禁止进入模型上下文、候选计算或图像输入。
- 前端来源颜色、文件名、编号来源前缀、真值均不得用作模型身份依据。
- 批量导入的接收序号可能相同，必须使用已处理前缀的明确观测允许列表隔离未来输入，不能只检查receipt_seq。

## 2. 控制流

接收/导入 → 校验去重并保存 → 组装队列 → 免费准备与授权 → 逐组判断 → 暂定工作状态 → 完成后人工确认 → 单独授权预测/绘图。

每步：读取一组 → 固定可见历史 → 准备接续/竞争证据 → Agent结构化判断 → 引用/互斥/数值校验 → 保存原文与结果 → 更新暂定状态 → 下一组。

没有历史的首组仅建立起始待定观测，可以免费初始化；不可宣称已识别方向/速度。归属不确定可继续下一组，技术错误/未知调用暂停，不自动重试。

## 3. 输入和顺序

- Observation：一条测量；Unit：一组提交容器；Run：固定范围、有顺序的运行队列。
- Unit有unit_id、观测引用、event_time、platform_id、组内绑定来源/可信性，容器不等于目标身份。
- 实验回放默认按event_time稳定排序，同时间不按文件来源或真实目标排序；实际接收按接收顺序。
- 缺阵、多候选不任意凑对；实验提供的组内绑定不能算算法配对成绩。
- 晚到历史点走历史修订，保留原先预测及当时知识范围，不包装成实时预测。
- 运行中新输入继续保存，不进入当前步骤快照，也不自动扩大授权范围。

## 4. 单步判决

- 指定物理目标时：核对绑定版本、接续合理性，不符合则待决/异常，不强行接入或偷偷切目标。
- 未指定时：比较已有轨迹，输出接续、暂定接续、暂定新目标、竞争归属、未归属。
- 主要证据为时间方位变化、历史趋势残差、时间间隔不确定性、跨阵一致性、运动变化与互斥关系。
- strength/峰宽仅辅助，sigma_deg不能直接当测角误差；没有空间证据不得补造距离经纬度。
- 保存竞争关系，允许后续证据修订本次暂定历史；改动既有确认历史必须形成修订提案。
- 模型不得引用不可见观测，不得重复确定占用；冲突隔离，不按输出顺序分胜负。

## 5. 状态与事务

- 原始事实、运行工作状态、用户已确认状态分层。
- 每步只更新工作状态，不通过调用旧review函数伪造“人工已确认”。
- Run：prepared/running/paused/completed_awaiting_review/failed/result_unknown/adopted/rejected。
- Step：queued/prepared/running/validated/held_for_review/failed/result_unknown。
- SQLite持久化队列、游标、输入单元；独立保存步骤快照、模型正文、用量、证据、校验结果。
- 浏览器刷新读取后端游标，不重发已完成/结果未知步骤；相同请求幂等。
- 每会话互斥、版本校验、原子提交；追加原始数据不能覆盖运行投影。

## 6. 模型及费用边界

- 默认每步一次结构化关联调用，后端预先准备真实证据；不自动循环工具/模型直到“满意”。
- 准备、去重、本地校验、已保存回复恢复不调用模型。
- 授权绑定队列范围/顺序、起始历史版本、接续范围、模型配置、协议、调用上限。
- 批量逐组调用必须在发送前显示最多N次；预算不足不自动增加max_calls。
- 暂停只阻止下一步，已发送调用完成保存；未知结果先核对，不自动重新计费。
- 默认整队列确认后另授权预测/绘图，不默认N次关联＋N次绘图。
- 预测点永远不当观测；后端数值证据不冒充模型绘制曲线。

## 7. 界面及接口

在现有/incremental工作台实施，不另开工作台。底部增加准备队列、执行下一组、连续执行、暂停、运行确认/打回；显示游标、新增/历史/待决/未处理数量。
右侧图表保留；来源对照与算法归属分开命名。完整流式正文和本步证据可查看，查看不重调。
沿用/api/incremental/mixed-sessions/{sid}命名空间，新增runs/preview、runs创建、run查询、next、start、pause、review及保存回复恢复能力。

## 8. 代码分工

- 逐组runner：调度、预算、游标、暂停、恢复。
- step context：只新增一组和已处理允许列表。
- working projection：暂定历史、竞争与修订。
- 现有mixed_prediction/association_wire复用严格校验及无损传输，但不能直接循环旧的“每轮人工确认”状态机。
- observations账本和现有文件库保留，旧会话/回复不破坏性迁移。
- joint_identity候选覆盖不足另列实施项，不以放宽几何门限制造空间图。

## 9. 验收清单

- AC01：20组建20步，每步仅新增一组；首组无历史可免费初始化。
- AC02：第8步上下文/候选不能含第9～20组，不能只靠接收序号过滤。
- AC03：下一步能参考已处理结果，竞争不阻塞队列；不自动确认用户历史。
- AC04：单阵、重复、乱序、历史补点正确处理，不丢原始观测。
- AC05：授权队列、模型配置、次数上限可检查；重复启动不重复计费。
- AC06：暂停、刷新、失败、未知调用均不自动重试。
- AC07：原始文件与已确认投影不被运行步骤覆盖；人工确认/打回可验证。
- AC08：逐组/连续执行、进度、原文、证据在现有工作台可见。
- AC09：预测单独授权，旧预测保留、未来点不进入事实历史。
- AC10：候选覆盖/截断信息可见，测试强度峰宽变化与去指纹数据，不预设三目标。
