# 独立线路推演工作区与Agent设计方案

版本：v2.0  
日期：2026年11月27日  
状态：需求与技术设计，待确认实施；未表示界面、接口或Agent已经上线。

## 一 本次需求更新

新增独立的“线路推演”工作区，入口放在现有左侧导航，与图片识别、轨迹工作台、数据生成工具并列。布局参考Codex的文件/会话侧栏、中央对话执行区、右侧成果面板。

这版取代v1.0中“直接在原轨迹工作台选择区增加模式”的界面安排。轨迹补全的数学边界保持：一次最多5个输入节点，包含确定的头尾；主要推演中间路线，最多保留5条可行竞争路线。

本方案将“旁边新开一个项目”落实为同一应用下独立页面、业务命名空间、会话和结果存储，不新建Codex聊天，不迁移或覆盖旧工作台，也不默认另建磁盘仓库或第二个服务。若后续明确要求独立仓库，可在业务隔离基础上拆出；不影响本次界面入口定义。

新增核心要求：每一步生成的图都可在右侧查看；中间节点必须能显示目标位置、hull/tow阵列位置、真实观测方向、候选连接及残差，不能只有最终折线。

## 二 业务目标与限制

1. 输入确定的同一目标起点和终点，中间最多3个观测或待预测时刻，总计不超过5个输入节点。
2. hull/tow同组数据作为一个复合节点，不计成两处目标位置；原始数据和两个阵列字段全部保留。
3. 文件可包含大量原始观测，导入文件不限制为5条；绑定到某次推演任务的输入节点才限制为5个。
4. 头尾保持固定。只有头尾时存在多种合理路径，模型可以推荐，但不得宣称唯一恢复真实轨迹。
5. 中间节点分别标记确定位置、带误差位置、双阵观测、待预测时刻。预测点不是实测证据。
6. 候选线路最多5条，与输入节点数无关；重复路线合并，不足不补造。
7. 有时间才进行真实速度、加速度与转向率检查；缺时间时进入空间路径模式，不虚构耗时。
8. 目标运动与平台导航分开。平台航向航速不能直接当目标运动。
9. 已知终点参与补全，不把结果宣传为未知终点的因果未来预测。
10. 未确认归属的中间观测须明确标竞争/未确认，首版要求用户先确认输入范围，不隐式执行大量混合目标关联。

### 页面和布局约定

- 新入口建议为 /route-lab，导航名称“线路推演”，明确与 /incremental 独立。
- 左侧文件栏和右侧图栏可拖动调宽、折叠；宽度保存为用户布局偏好，不进入模型输入。
- 中央消息独立滚动，输入区固定在中央列底部，不遮挡左右栏，也不随长日志跑到页面外。
- 右侧是一个成果检查器，不是堆叠所有大图的长页面；采用标签页＋阶段缩略图＋选中成果大图。
- 切换历史节点/候选/版本只读已保存成果，不重新调用模型。
- 各区都有空态、加载态、失败态；窗口缩小时可切换抽屉，避免画布被挤成不可读细条。

## 四 文件导入与独立项目数据

### 文件角色

| 角色 | 读取内容 | 可否直接成为模型事实 |
|---|---|---|
| 观测文件 | 时间、阵列、方位、质量等 | 仅限用户绑定到本任务的节点 |
| 平台配置 | 平台位置、航向、航速、阵列偏移 | 可作为观测几何依据，不是目标状态 |
| 端点配置 | 用户明确指定的确定头尾及可选目标运动 | 可作为任务边界 |
| 参考评估 | 真值路线或参考图 | 仅事后评估，不进入盲评输入 |
| 未识别文件 | 不自动推断内容用途 | 显示格式提示，等待用户选择 |

支持磁盘ZIP和JSON。ZIP继续采用受限内存读取，检查路径、条目数、大小、格式及平台兼容性，不运行压缩包内脚本，不跟随文件内路径读取任意本机资源。

导入保存文件后展示“起点/终点/加入中间节点”操作；不能自动把整个文件都发给模型。选择第6个节点时阻止并说明。来源名称仅用于浏览和审计，不作为模型判断哪个目标的答案。

起终点若来自含参考信息的文件，必须由用户明确选择授权；记录本次为“给定端点的条件补全”，不得称为完全不使用参考信息的盲测。隐藏的真实中间路线仍不允许进入推理。

### 生命周期

- 新工作区拥有独立会话和运行ID，不沿用旧工作台的active_run及模型授权。
- 新建会话可以直接使用新工作区文件库中的旧文件，不强制重新上传。
- 删除会话不删除文件；删除文件需明确操作，历史任务保留已绑定输入快照并提示源文件已移除。
- 从旧工作台带入数据使用显式“复制到线路推演”，不共享可变任务状态、不修改旧会话。复制时保留来源和新文件标识。
- 初版以服务器独立文件库和SQLite为权威，浏览器IndexedDB仅缓存布局、草稿和只读副本，不形成两份业务权威。导入会把用户文件传给本机后端，但不会自动传给模型。
- 本机独立存储不等于云备份或公网多用户权限体系。首版沿用本机部署边界，不新增未经设计的公网入口。

## 五 一次推演的使用顺序

1. 点击“线路推演”，新建会话。
2. 拖入ZIP/JSON，或打开文件库已有文件。
3. 明确选起点、终点，再选最多3个中间节点或待预测时刻。
4. 核对目标运动、平台导航、时间和误差条件；缺项显示待补充或明确降级。
5. 点击“生成候选（免费）”，右侧逐步出现边界图、几何图、候选路线和指标。
6. 点击“准备Agent评判（免费）”，核对将发送的数据、模型和次数上限。
7. 授权后执行主评判；若预先授权条件复核，必要时再执行一次质疑复核。
8. 中央显示实际节点结果与模型正文；右侧同步显示候选比较、推荐、竞争或拒绝原因。
9. 用户可预览任意候选，显式确认工作路线；人工选择与模型结论分别保存。
10. 加入新中间观测后建立新版本，重新免费准备；任何新增付费评判重新核对授权范围。

聊天可以表达要求，但不是绕过结构化输入的通道。明确修改端点、运动边界等动作先生成变更草稿，由用户确认；文本不自动覆盖确定事实。无法可靠解析的要求让用户在对应表单确认，不偷偷增加一个付费意图识别Agent。另行请求模型解释时也必须纳入显式调用预算。

| 成果 | 产生阶段 | 显示内容 |
|---|---|---|
| F01 输入边界图 | 输入校验后 | 固定头尾、真实中间观测、平台导航及时间范围 |
| F02 中间节点双阵几何图 | 几何准备后 | 当前时刻阵列位置、观测射线、候选位置、镜像和残差 |
| F03 候选路线图 | 路线生成后 | 最多5条路线、输入节点、生成假设及搜索范围 |
| F04 可行性诊断图 | 约束检查后 | 速度/加速度/转向曲线及超限区间；无时间则不显示物理时序图 |
| F05 观测符合性图 | 指标完成后 | 实测与候选回投、分阵残差、中间位置残差 |

| F07 版本调整图 | 新观测版本后 | 旧工作路线与新路线、改变区间及改选原因 |

每份成果携带artifact_id、run_id、revision、node_id、input_digest、候选集哈希、算法版本、数据性质和生成时间。重试成果额外标明attempt_id，避免把失败尝试的图当成最终成果。

前端主要使用后端保存的坐标、曲线参数和指标渲染SVG，不让大模型画示意图代替业务计算。PNG/SVG导出从同一结构化成果生成。显示单位、比例尺、数据/示意属性和缺项；图可随节点完成出现，不必等待整次任务结束。

### 中间节点双阵图的强制规范

按用户示例实现，提供候选切换和中间时刻切换：

- 蓝色或当前候选强调色圆点：候选目标在时刻t的位置，标记“R002 · 100秒 · 预测位置”等，不假称实际位置。
- 白色方块：实际导航模型计算的hull、tow阵列位置，使用该时刻而不是t=0的位置。
- 灰色虚线：真实观测允许的方向；折叠方位保留合法镜像射线，并明确分支。
- 蓝色连接线：阵列到该候选位置的几何连接，用于计算预期方位，不强行旋转成实际观测方向。
- 候选路线：同候选固定颜色，显示附近路线或完整路线，并标固定头尾。
- 表格：阵列、实际方位、候选计算方位、折叠一致的方位残差、误差/容差来源。
- 与观测不符时连接线和残差明确警示，不能把两条观测射线重新画到候选点上制造交会。
- 缺少真实双阵观测时，仅显示候选预期方位并标“无实测对照”，实际观测和残差为未提供，不填0°。
- 缺导航则不能画真实阵列位置；展示缺项，不拿任意白方块当平台。
- 没有时间时只对明确的空间节点作示意，不生成虚假的100秒标签。
- 东北坐标同尺度，禁止横纵独立拉伸。大场景基线太短时用等比例局部放大插图，不只放大基线而伪造方位几何。
- 图中中间位置应标明实测、条件交点或路线预测，三类符号不同。

镜像位置只有在满足已固定头尾及其他条件时才是合法路线候选。不能复用旧工作台“整条镜像”操作随意移动本任务的已知端点。

## 七 数值路线算法

### 主方法

沿用v1数学方案：有限分层候选图搜索＋分段三次Hermite曲线参数化＋SLSQP约束优化。

Hermite可表达节点位置和速度，默认C1连续；本方案显式增加多段连接处加速度连续条件，不将C1误称为C2。SLSQP为局部约束优化器，不保证全局最优或穷尽所有路线。依据：[SciPy Hermite](https://docs.scipy.org/doc/scipy/reference/generated/scipy.interpolate.CubicHermiteSpline.html)、[SciPy SLSQP](https://docs.scipy.org/doc/scipy/reference/optimize.minimize-slsqp.html)。

### 处理顺序

1. 统一坐标和正反观测模型，目标和平台分别建模。
2. 端点和中间已知状态作可达性必要条件预检。
3. 构建最多3个中间搜索层；已知观测按其时刻建层，缺失层可作内部预测搜索层，不算新实测。
4. 在公开搜索区域内产生不同方向、转向时机和速度假设的种子。
5. 有界搜索保留有限种子，优化未知中间位置、速度与必要的曲线参数。
6. 全区间检查位置边界、时间、速度、加速度及转向条件；不能只抽查5个节点。
7. 去除不合法和重复路线，按观测支持与差异保留最多5条。
8. 保存所有被剔除原因和搜索截断信息；没有路线时区分约束矛盾、数值失败和搜索不足。

资源预算拟议默认：每中间层最多5个位置初值、搜索束宽16、最多12条优化种子、单种子最多200次迭代、总软时间预算5秒、保留最多5条路线。这些不是已测试性能或精度承诺；若含速度离散，实际状态数量必须另计并受总预算约束。

边界固定；已声明目标能力作为硬条件；中间不确定测量按误差模型形成残差。加速度及速度极值在分段多项式内检查，转向率采用保守有界检查，低速时标记航向不可定义。无法验证的候选不能通过硬门槛。

路线生成的平滑/运动代价只是先验，不是目标真值。只剩一条候选时仍只代表本次搜索结果，不代表唯一物理解。

## 八 Agent总体定位

本期采用“受约束、可检查点恢复的人机协作工作流Agent”，不是无限自主循环的通用ReAct系统，也不是固定多Agent聊天投票。

采用真正的LangGraph StateGraph编排业务节点，配置持久化checkpointer；工具、模型、人工批准和发布分别设节点。沿用项目已有LangGraph框架，但新图、新State、新业务表和新thread_id命名空间独立，不能把原图片Agent直接改名当成本功能。

LangGraph支持检查点、人工中断和更新/自定义流。官方说明中，中断恢复可能从节点开头重新执行，因此收费请求和非幂等副作用不能放在批准节点前，也不能仅依赖检查点声称外部调用恰好一次。参考：[检查点](https://docs.langchain.com/oss/python/langgraph/checkpointers)、[人工中断](https://docs.langchain.com/oss/python/langgraph/interrupts)、[流式更新](https://docs.langchain.com/oss/python/langgraph/streaming)。

### 职责划分

| 角色 | 是否调用模型 | 权限与目标 |
|---|---|---|
| 编排器 | 否 | 根据状态和规则选择下一节点、控制预算和版本；不替模型选择真实路线 |
| 证据工具层 | 否 | 读取绑定节点、求几何、生成路线、计算指标和图形数据 |
| 主评判Agent | 是 | 对完整允许候选进行证据比较，选择/推荐/保留竞争/拒绝 |
| 条件质疑Agent | 按需是 | 检查关键证据冲突、选择缺乏支撑、镜像等问题，不是默认多次投票 |
| 结果裁决器 | 否 | 检查结构和证据、处理两次判断冲突；不能按本地最低分强行指定真路线 |
| 人工确认节点 | 否 | 允许用户确认工作路线或补充资料，保留与模型决定的区别 |

“Agent”不是每个程序节点都调用模型。正常只需1次主评判；额外质疑只在已授权条件满足时发生。同一模型进行第二角色复核不保证独立性，应如实记录模型和提示版本。

```text
  └─ 新中间观测 → revision+1，生成F07并从G02重新准备
```

图结构由代码固定，模型不能新建图边、提高预算、修改起终点或跳过人工授权。人工补充输入创建新版本，不把已冻结版本原地改成另一组事实。

### 关键节点的输入输出

| 节点 | 关键输入 | 关键输出/停止条件 |
|---|---|---|
| G03 证据整理 | 绑定节点、运动配置、文件角色 | evidence_inventory、missing_fields、assumptions |
| G04 固定范围 | 合法输入和配置 | input_digest、scoring_version、revision |
| G05 几何 | 时间/坐标、平台导航、双阵观测 | 位置/射线/回投基础、F01/F02及缺项 |
| G08 候选求解 | 边界、候选图、运动限制 | 候选参数、种子假设、截断与失败信息 |
| G09 检查计分 | 曲线、实测、误差模型 | admissible_routes、metric_table、F03/F04/F05 |
| G13 主评判 | 冻结候选、指标和证据 | 严格结构判断＋简短可核查理由 |
| G16 质疑 | 相同冻结事实、主判断和需复核项 | 支持/质疑/不可区分及具体证据 |
| G18 裁决 | 已校验主判断、复核及工具证据 | 工作选择、先验推荐或竞争，不能捏造“共识” |
| G19 发布 | 当前版本、决策和产物 | 不可变结果及可恢复事件，人工采纳仍分开 |

## 十 主评判Agent详细协议

### 输入内容

使用route-lab-review-context-v2，包含：

1. run_id、revision、上下文摘要及候选集哈希。
2. 用户任务、确定头尾、最多3个中间节点及其事实性质。
3. 目标运动约束，平台导航和测量模型分别提供。
4. 合法候选ID、曲线参数、少量可读采样、完整关键指标、逐中间观测的残差和假设。
5. 分层评价规则、可辨识性检查、搜索限制和缺项。
6. 本版本允许使用的证据ID和可选路线ID。

不输入无关全文件观测、隐藏真值、原始轨迹身份标签、认证信息或旧会话无限聊天记录。已知头尾是明确的合法条件，来源标签不是中间关联答案。聊天问题不能改变固定系统协议。

### 评判顺序

第一层：只考虑程序准入通过的路线，不能替程序放宽硬约束。

第二层：比较中间位置或双阵实测的符合程度。对折叠方位按同机制计算残差；误差未标定时只比较显式容差代价，不生成正确概率。

第三层：比较可信目标运动先验，再比较无依据机动与复杂度。所有合格路线都经过头尾，因此端点残差不是区分中间真假的主要证据。

第四层：保留不可区分者。没有真实中间证据时最多称为先验推荐，不允许用漂亮曲线、密集采样数或模型自报置信度冒充证据。

规则采用分层比较，不预先固定未经验证的70/20/10总分。优化代价权重、误差容差及比较阈值均版本化，由开发集确定，再在独立保留集评估，不能针对参考答案临时调分。

### 输出

```json
{
  "format": "route-lab-judgement-v2",
  "revision": 2,
  "context_digest": "example_digest",
  "decision": "ambiguous",
  "selected_route_id": null,
  "preferred_route_id": "R002",
  "competing_route_ids": ["R001", "R002"],
  "selection_basis": "prior_preference",
  "reason_codes": ["insufficient_middle_evidence"],
  "evidence_refs": ["metrics:R002.motion", "observations:M1"],
  "explanation": "两条路线均满足头尾，现有中间观测不能区分；R002仅运动先验代价较小。"
}
```

示例只是格式，不是实际运行结果。decision只允许selected、ambiguous、reject_all；selection_basis区分observation_support、prior_preference、insufficient。preferred与selected是不同字段。

explanation用于用户可读说明，不是隐藏思维链。原始模型正文按实际服务返回保留，不承诺提供服务未返回的内部推理。

## 十一 条件质疑Agent和冲突处理

### 触发条件

- 主判断选择的路线存在明确的未回应观测矛盾。
- 模型把先验偏好写成实测确认。
- 两条路线在现有观测下几乎不可区分，主判断却未保留竞争。
- 新观测导致与上一版本大幅改线，需要核对引用和变更依据。
- 用户显式要求复核，且已经授权相应调用。

纯JSON错误优先走原节点结构重试，不增加一个质疑模型替它修JSON。可在本地直接确定的错误先按协议拒绝，不让另一个模型投票决定是否合法。

### 质疑输入与输出

读取与主评判完全相同版本的事实和指标，另带主判断及questionable_claims。不得读取参考真值。输出可为support、challenge、indistinguishable，并必须引用具体观测/指标及受影响候选。

质疑Agent不得新增路线或数值，不得仅说“我认为另一个更好”。复核角色使用同模型时标明同模型角色复核，不宣传为两个独立专家相互验证。

### 裁决规则

- 两者一致且规则通过：保留工作结论，依然不是人工确认或真实路线证明。
- 质疑引用了可核查的规则/证据冲突：程序检查该事实；主结论不能无条件继续作为观测确认。
- 两者意见不一致且程序无法定论：保留竞争，等待新观测或人工选择。
- 复核超时未知：保留原主判断和复核未完成标记；不得自动称复核通过。
- 不开第三个裁决模型反复争论，不设置“讨论直到一致”的无限循环。

## 十二 工具权限和行动边界

本期工具由工作流节点按固定顺序调用，模型不是任意发起shell/文件工具的通用助手。工具结果都有artifact_id和input_digest，模型只能引用允许证据。

| 工具 | 作用 | 副作用与限制 |
|---|---|---|
| read_bound_nodes | 读取本任务绑定节点 | 只读，最多5节点，不读取整个磁盘 |
| resolve_navigation | 读取已授权平台配置 | 只读，不替换目标状态 |
| project_geometry | 坐标和双阵几何 | 纯计算；不确认身份 |
| generate_route_candidates | 有界候选搜索 | 只生成当前版本候选，不修改头尾 |
| evaluate_route | 全区间运动和观测指标 | 纯计算，不使用参考真值 |
| compare_routes | 比较合法候选 | 返回差异与证据，不输出真实身份结论 |
| render_artifact | 保存结构化图形 | 按版本写允许目录，不任意写文件 |
| request_model_review | 调用主评判或质疑 | 仅经预算及授权闸门；记录调用意图 |
| publish_result | 发布工作结果 | 仅编排器在版本校验后执行 |
| accept_route | 人工采纳 | 只能来自显式用户操作，模型无权调用 |

首版不允许模型自行增大候选范围、放宽速度、查参考文件或要求重新发送未知请求。模型认为证据不足只能提出结构化缺项/复核建议，由界面展示给用户。

## 十三 State与记忆设计

```text
RouteLabState
  identity: workspace_id, conversation_id, task_id, run_id, revision
  scope: node_ids, endpoints, temporal_mode, input_digest
  evidence: bound_nodes, navigation_ref, target_motion, assumptions
  policy: algorithm_version, scoring_version, tool_limits
  geometry: artifact_refs, observability_report
  candidates: candidate_set_id, route_ids, admissible_ids, metrics_ref
  review: primary_ref, challenge_ref, final_working_decision
  display: artifact_refs, active_stage
  control: phase, pause_requested, expected_revision, pending_approval_id
  billing: authorization_id, allowed_roles, attempt_limit, used_attempts
  audit: event_cursor, parent_revision, changed_intervals
```

- credentials不进入State或模型快照；文件二进制和大图只存受控引用，不塞进每个检查点。
- 用户的预览候选、模型选定候选、模型先验推荐和人工采纳结果分别保存。
- LangGraph thread_id映射到一次run；不同输入revision使用新的run/thread，避免旧图继续执行时混入新事实。
- 业务候选、尝试账本和成果以业务数据库为权威；检查点保存编排进度及相同版本引用，不承担外部计费系统的恰好一次保证。
- 本地使用持久化SQLite checkpointer，依赖需在实施时核对并固定兼容版本，不能使用InMemorySaver冒充重启恢复。
- 检查点恢复先核对业务账本：有合法已保存结果则复用；dispatched但无明确结果的模型尝试标未知，不能由图恢复机制自动重发。

## 十四 费用授权和有界执行

正常路线评判1次主模型请求。准备页面可选择是否允许条件质疑；若允许，最多再1次质疑请求。每个角色最多额外1次格式/明确语义协议重试，不把正常待定当异常。

| 策略 | 正常基础调用 | 可能附加 | 最大授权上限 |
|---|---:|---|---:|
| 仅主评判，不重试 | 1 | 无 | 1 |
| 主评判＋一次格式重试 | 1 | 主评判重试1次 | 2 |
| 主评判＋条件质疑，不重试 | 1 | 命中条件时质疑1次 | 2 |
| 主评判＋条件质疑＋有界格式重试 | 1 | 质疑1次，两角色各最多重试1次 | 4 |

只有命中条件且授权含质疑，才可使用其预算；未用次数不代表费用发生。这版默认主流程仍1次，复核属于明确新增可选能力，不将“Agent更详细”变成隐式多次收费。

批准绑定输入哈希、候选集哈希、模型指纹、角色、次数上限和revision。任意关键项改变都使原批准失效。暂停只能阻止尚未发出的请求，不能承诺取消已发到上游的计费请求。

模型调用前业务事务登记attempt_id、幂等键和dispatched意图，再请求外部服务；不持有SQLite事务等待网络。服务崩溃时若无法确认是否发送/执行，按未知处理。即使LangGraph节点重跑，也必须经过账本检查，不自动多付一次。

## 十五 流式过程与图形同步

后端事件采用带单调event_seq的持久化事件流，经SSE只读传输，建议事件包括：

```text
node.started / node.progress / node.completed / node.failed
artifact.created / candidates.ready
approval.required / model.started / model.delta / model.completed
review.challenged / decision.published
run.paused / run.result_unknown / run.completed
```

节点事件来自真实执行，不用定时器假装“已分析”。模型正文增量仅在上游适配器真正支持时发送；否则显示等待状态和耗时，完成后展示全文，不伪造token流。

图通过artifact.created逐步出现：输入完成即可看边界图，几何完成即可看节点交会图，候选完成即可切换线路，评判完成再显示模型推荐。流式JSON未完整校验前不改正式工作路线。

每条事件附run_id、revision、node_id、event_seq；模型相关另附attempt_id。前端按游标去重，不把重连内容重复追加。断开后用Last-Event-ID或等价游标补事件；服务端若已清理旧事件，先恢复完整快照再继续。

GET状态/事件失败只重连查询，不发模型POST。心跳与“业务有进展”分开，显示最后事件时间、当前节点和服务是否可达；未知结果不因页面恢复而自动变成running。

## 十六 存储与一致性

建议目录为 outputs/route_lab，独立于旧mixed_prediction结果；业务SQLite和图checkpointer分开管理，实施时固定明确路径。

业务表建议：

- rl_files：独立文件及角色、hash、删除标记。
- rl_conversations：会话、消息与布局引用。

首版明确单服务进程调度并对同run加锁；若扩展多进程，需数据库租约/锁和并发批准防护，不只依赖Python内存锁。凭run_id访问不构成公网权限控制，本期仍按本机服务部署。

## 十九 验收与测试

### 界面与文件

- 新导航可进入独立页面，原入口仍可用。
- 删除新会话不删文件，旧数据可用于新会话。
- 导入不调用模型，绑定节点不超过5，hull/tow复合计数正确。
- 左右可拉伸、底部固定、阶段图与中央节点联动，刷新后可恢复同版本。

### 几何与算法

- 固定头尾不漂移；目标/平台运动不混用。
- 实际射线、候选连线和残差表由同一观测模型生成；不存在先把射线对齐候选再报0差。
- 缺观测显示未提供，缺时间不标真实秒数，缺平台不画伪真实阵列位置。
- 所有候选通过整段约束检查；曲线段内极值、低速和转弯边界有测试。
- 候选去重、无解/搜索不足区分、可用镜像必须满足固定端点。

### Agent与收费安全

- 主/质疑输入哈希、版本和候选ID严格绑定；非法引用、篡改指标、无证据确认均拒绝发布。
- 无中间证据必须保留先验性质；不能仅靠多角色一致升级为真实确认。
- 测试所有条件边、预算耗尽、未授权质疑、重试一次、有效待定不重试、未知不自动发。
- 中断恢复、重复execute、批准重放、崩溃在发送前后、流断开及跨版本结果到达均不得静默重复收费。
- 节点和图成果来自真实执行；上游不支持token流时不伪装实时模型正文。

### 真实模型与隐藏点评估

只给确定头尾及最多3个中间观测，隐藏其余真实中间点；参考在推理结束后评估。分别报告候选集中最好路线的事后误差、模型实际选路误差、选择差距、无法区分的情况、观测覆盖、约束违反、耗时及真实请求数。

候选最优只能作为算法上限评分，不得把事后选出的最佳路线替换为模型实际决定。误差小但大多数点没使用、或模型仅先验推荐的结果不能包装为完整识别成功。
