# 双阵持续亮带身份复核

## 本轮目的

修复两类错误：同一连续观测被模型拆成不同ID，以及同一模型ID跳到无关亮带。程序现在在数量清单复核之后、空间定位之前运行真实LangGraph节点`identity_reconciliation`。

## 算法边界

1. 仅根据已保存/已上传候选表重建两阵局部tracklets，不读取truth、meta、semantic、参考图或指定目标总数。
2. 匈牙利匹配若存在竞争（替代成本接近）或预测偏差过大，将连接两侧候选标为歧义。歧义和缺行切断局部身份段，不能自动跨交叉接续。
3. 每组已通过基础校验的模型配对，映射到“平台＋hull连续段＋tow连续段”。只有两个连续段都一致，才属于同一H身份假设；模型名称不决定身份。
4. 同一双阵持续段中不同模型ID的前后观测可归入同一H；同一模型ID跳到其他持续段时分开。只有一个同步时刻、局部支持不足或交叉竞争的点隔离，不送定位。
5. 缺少的模型观测不补；同H不同时段仍分branch。角度、时刻和候选编号保持原样，记录每点原模型ID/branch。定位误差门限本轮未改。

## 不能声称什么

H是连续身份假设，不是真实目标ID。同一真实目标可能因交叉/漏检分成多个H；错误局部tracklet仍可能形成错误H。因此不按H数量宣布目标总数，不承诺已找全四个目标，不保证位置误差已降低，也不会恢复模型未选择的目标观测。

前端分开显示原模型ID数量、H身份假设数、可定位H数。身份映射和被隔离的点见identity_report.json；原始配对见model_observations.json，实际送入定位的配对见resolved_observations.json。

## 本地无费用重处理

```powershell
python -m backend.scripts.reprocess_identity 20261117_122003_378e20c8
```

只读源结果中的候选、标定和原模型正文，在新结果目录中重跑本地后处理；不覆盖源记录，不读真值，不调用模型。执行报告记录source_result_id与new_model_calls=0。历史界面不把源模型用量重复当作本次用量。

## 验证

合成用例覆盖：跨ID连续段合并、同ID不同亮带拆分、交叉竞争隔离、缺测不补、平台隔离、候选数与模型ID数分离、无模型调用的本地重处理。

对20261117_122003_378e20c8的原回复本地重放：23组配对保留15组、隔离8组，模型T1 main与T2 main归入H1；共保留2个连续身份假设，最终仅H1通过空间检查。与旧版相比去除了部分身份串线与重复ID，但仍未恢复完整四目标，也没有新的真实模型准确率结论。
